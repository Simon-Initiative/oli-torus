# MER-5865 step-4 proof-contract design read — reopened v3

## Blockers

1. **B4-EXIT / §1, §3, and §4 — the ten record variants are not a closed inventory of driver exit sites.** The §3.2 union closes the shape of operation-failure records once produced; it does not prove that every non-green `throw`, rejected await, early return, catch branch, or cleanup failure in the future driver reaches one of those producers. Fault-injecting one named producer per union member can make EMISSION green while another code path exits before record construction and has no row to inject. That is the exact silent-exit class B4-EXIT is supposed to exclude. The open-window boundary clause detects a supplied/suppressed record in a known branch, but it cannot discover an unenumerated branch. Pin an independently checked control-flow inventory of every non-green driver/fixture exit site to exactly one typed producer (including the outer error/finally boundary), mutate each site before its producer, and fail the artifact when the code contains an exit site absent from that inventory. The record-tag inventory remains the MAPPING reference; it cannot double as the EMISSION-completeness reference.

2. **B4-CORE-L / B4-REG / §1 and §4 — the detailed witnesses do not fully implement the claimed substitution proof, and the registry “live” witness is rejected by MAN first.** §1 and CORE-L require bypass **and substitution** for attribution, planner, permits, oracle, and registry, but §4 specifies only bypass mutations. In particular, “oracle bypass → ENTRY-L's verdict-not-from-auditRun check” cites a check that ENTRY-L does not claim or witness; ENTRY-L only proves live journal-issued fence seqs. A lookalike planner/attributor or an ignored oracle result can therefore coexist with the required imports unless the mutation changes that consumer's result on an exercised live branch and the switched entry point demonstrably consumes it. Likewise, changing the manifest to a wrong family is already red at B4-MAN's raw-archive comparison, so it does not prove the live resolver is load-bearing. Require discriminating per-consumer substitutions with imports/seqs/MAN held green: alter planner output on a live branch, ownership, permit issuance, audit result, and a post-validation registry resolution to a wrong-but-valid entry; each must fail at its named downstream locus.

3. **B4-SUITE / §1, §3, and §4 — a scan of the post-change test sources is still a self-shrinking reference.** At a gate revision, deleting or renaming an `adaptive-` file removes it from both the file-scan inventory and the standing Playwright command, so exact equality can remain green. If “pinned revision” instead means the pre-step-4 revision, the contract does not define how required new step-4 tests join the inventory without restoring writer selection. The scan also lacks a closed derivation for generated identities: `adaptive-oracle.spec.ts` creates sixteen tests with `for (...) test(name, ...)`, so a textual declaration scan is not coextensive with Playwright discovery and can be spoofed by equivalent aliases or generation. Fix the expected set to the independently reviewed pre-change inventory plus an explicit additive step-4 test manifest (no unexplained removals/renames), and validate the enumerator against generated/aliased declarations or use an independent canonical discovery mechanism. Pinning the same mutable source tree that execution consumes does not establish subset completeness.

## Should-fix

1. **B4-REG / B4-EXIT / §3 and §5 — two rows still violate the exact three-class, atomic-row protocol.** REG uses `IA (matrix) + CI (live)` and EXIT uses `CI (mapping) + IA (inventory)` in one Class cell. The protocol permits exactly one of IA/IS/CI per atomic row; the whole reason for splitting ENTRY/CORE was to prevent one independent leg from lending its label to a capture-internal leg. Split REG static-contract versus live-use claims, and split EXIT inventory, emission, and mapping claims. Composition can then require every row without treating the combined label as an independent anchor.

2. **B4-C4A / B4-C12a / §3–§4 — snapshot timing should be normative, and one listed mutation overclaims the setup-section anchor.** The DOM-prop source is acceptable as an `IS` leg because it is a different server-rendered source from the finalization record and the shared page/process is disclosed. The contract should nevertheless require the fixture to capture and freeze it immediately after opening the intended Delivery page and before the driver or any subsequent navigation; otherwise a late reader can snapshot the navigated-to run it is meant to judge. Also, mutating the snapshot to match a forged finalization is caught by `setup.sectionSlug` only when the section changes; a revision/attempt-only common-mode substitution preserves that leg. Narrow that witness to the fields the setup response actually anchors, and add a post-snapshot navigation/DOM-replacement witness that retains the original triple and rejects the later finalization.

## Summary

**Counts:** 3 blockers, 2 should-fix, 0 nits.

**Verdict:** **REDESIGN**. V3 is materially closer and discharges seven of ten round-2 findings, but the gate can still accept an unenumerated silent driver exit, a non-load-bearing lookalike consumer, or a strict suite whose expected inventory shrank with the branch under judgment. This is a proof-design verdict only, never pre-approval of the implementation or gate evidence.
