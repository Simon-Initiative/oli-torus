## Description

Implement the reusable preview-user resolver and Reset Preview User action described in MER-6220, including durable ownership markers and a separate current author association.

## Technical Guidance

Reuse `author_settings_live.ex`, the author/account schemas, and generated-user creation in `lib/oli/delivery/sections.ex`. Keep preview linkage separate from normal `users.author_id`/SSO linkage. The resolver reuses the current user or creates one on first use; reset creates a replacement and switches the association atomically. Keep old users and their markers so they remain identifiable after reset. Exact schema/helper names are engineering choices.

Provide the shared enrollment-role rule: instructor for admin-owned preview users, student/learner for regular authors. When an author is promoted to admin, update their current preview user's existing section enrollments to instructor through the author role-change flow in `lib/oli/accounts.ex`. Keep the same user and progress. If no preview user exists, leave creation to first use.

Project and admin Stories apply this rule when enrolling users, including replacements after reset. Their launch/session flows remain separate from this task and are not prerequisites for account settings.

## Acceptance criteria

- An authenticated author can reset only their own preview user and receives accessible success/failure feedback. Later resolver calls return the replacement.
- Concurrent first-use/reset leaves one current association; failure preserves the old one. Repeated reset retains queryable current/superseded purpose and ownership.
- Preserve real authentication, learner/SSO linkage, old attempts/progress, shared sections, and other authors. No fallback to real/shared users, cleanup, deletion, retention process, or explicit progress clearing.
- The shared role rule selects instructor for admins and student/learner for regular authors. Promotion upgrades the current preview user's existing enrollments without changing its identity or progress, creating a missing user, or granting global admin permissions. After reset, new enrollments use the author's current role.
- Cover all parent Story account/resolver criteria independently of project/admin integration.
