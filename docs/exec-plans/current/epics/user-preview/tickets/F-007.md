## Description

**Figma frames / prototype:** [Figma](https://www.figma.com/design/S8qAFhjjlnRyTHCg2Dyb8p/User-Preview-Overhaul?node-id=484-13490&t=5eBSflw0qUqbFcPl-1)

### User Need

As an author, I want to preview an entire published course with student-facing navigation, so that I can review its content, structure, and flow as a complete learning experience. I need to know which published version I’m viewing and whether draft changes are excluded.

### Acceptance Criteria

**Successful behavior**

- Update the **Review** page layout according to Figma, preserving existing review functionality and the chart.
- Add a **Full course preview** card with the following states:

| **Project state** | **Card content** | **Available actions** |
| --- | --- | --- |
| **Never published** | Explain that the project must be published before full course preview is available. | **Go to publish** |
| **Published, with no draft changes** | Identify the published version used for preview and explain that full course preview uses published content. | **Open full course preview** |
| **Published, with draft changes** | Identify the published version used for preview and show the number of draft changes excluded from it. | Primary: **Open full course preview**. Secondary: **Go to publish** |

- Selecting **Open full course preview** opens the latest published version on the **Learn** page.
- The preview provides student-facing course navigation, allowing authors to explore the entire published course.
- Use the existing template course-preview experience as the basis for this behavior **but update the exit preview to the primary button for contrast reasons.**
- Selecting **Go to publish** navigates to the project’s **Publish** page.
- On the **Publish** page, add a **Preview published course** action next to the latest publication version. It opens the same full course preview.

**Exceptions and safeguards**

- Full course preview is unavailable until the project has been published.
- Unpublished draft changes are excluded from full course preview.
- Both entry points open the same latest published version.
- Preserve the existing Publish table UI; the new table design shown in Figma is outside this scope.

### Accessibility Requirements

- **Keyboard:** All preview and publishing actions must be keyboard operable, follow a logical focus order, and have visible focus indicators. Course navigation within preview must remain keyboard accessible.
- **Semantics and labels:** Give the card a programmatically associated **Full course preview** heading. Use descriptive accessible names for actions and expose publication details and excluded draft counts as readable text.
- **Focus and navigation:** If preview opens in the same tab, manage focus to identify the destination page. If it opens in a new tab, communicate that behavior in advance. Ensure authors have a keyboard-accessible way to return to their authoring context.
- **State communication:** Communicate availability and excluded draft changes through text rather than color alone. If the card updates dynamically, announce the updated status without moving focus.

## Preview identity integration

Use the reusable author-linked preview-user resolver and Reset Preview User capability delivered by [F-010](https://eliterate.atlassian.net/browse/MER-6220). This Story owns applying that identity to project launch, enrollment, rendering, navigation, activity requests, and exit. Preserve actual-author project authorization and normal learner/SSO sessions. Both Review and Publish use the same current preview user across projects; launches after reset use the new identity with fresh progress. Reject unauthorized or stale identity contexts and provisioning failures without falling back to real learners or shared hidden users. Admin section-preview integration is delivered by [F-001](https://eliterate.atlassian.net/browse/MER-6211).
