## Description

Use MER-6225's authorized preview user throughout section controller, LiveView, adaptive, activity, and affected admin product/template preview paths.

## Technical Guidance

Update `UserAuth.auto_enroll_admin/2`, `TemplatePreview.resolve_launch_identity/2`, and the second hidden-user lookup in `ProductsController.preview_launch/2` so they do not substitute a shared user. Cover `PageDeliveryController.page_preview/2`'s admin-without-current-user adaptive entry. Keep necessary non-admin legacy helpers.

Do not log the browser in as the generated user or replace its authentication token. Before enrollment/page/attempt loading, validate the owning admin, current user association, and section; use the preview user only for those requests. Carry that validated context through navigation and activity calls, independently of the real learner login. The route still selects presentation. Reuse existing signing and delivery setup; exact transport/helper names are engineering choices.

## Acceptance criteria

- Both perspectives, adaptive entry, rendering, navigation, and activity requests use the intended user without another fallback substitution. Switching keeps enrollment, resource, and original safe return.
- A real learner tab and admin preview of the same section can interact without changing one another's user/progress. Two admin section previews also remain independent through refresh/reconnect.
- Entry/exit preserves actual-author and real learner/SSO authentication. Reset selects the replacement on subsequent entries; stale, forged, revoked, or logged-out contexts are rejected at the request boundary.
- Preserve ordinary instructors, non-admin templates, and separate author-page/question previews. Do not add instructor controls to project preview. Verify this integration without waiting for the project-preview Story.
