## Description

## Scope

Connect the admin identity/enrollment capability to section controller, LiveView, adaptive, activity, and affected admin product/template entry paths.

## Acceptance criteria

### Positive

- Authorized admins enter both perspectives, including adaptive entry, with the intended preview user. Switching keeps identity, enrollment, resource, and original safe return.
- Controller, LiveView, activity, and affected admin template paths use that same identity without a second fallback lookup substituting a shared user.
- After user reset, subsequent entries use the replacement and fresh progress. Verify authorization failures at the integrated request boundaries.

### Negative

- Ordinary instructors, real learner/SSO sessions, and non-admin template behavior remain unchanged.
- Project preview does not gain instructor controls; author Page Preview and Question Preview remain unchanged. Admin integration can be verified without waiting for project-preview delivery.

## Technical Guidance

Consume MER-6225's authorized identity/enrollment capability and MER-6224's selector. Update affected admin auto-enrollment and both template identity-resolution/fetch paths so no second shared-user substitution occurs. Apply the same selected identity to rendering, navigation, and activity requests while preserving actual-author checks and normal sessions. Keep required non-admin legacy helpers. The session-preservation section below defines the approved request boundary and concurrent-tab checks.

Use the parent [F-001](https://eliterate.atlassian.net/browse/MER-6211) for shared feature requirements, design sources, and code evidence. This sub-task is complete when its scoped acceptance criteria above and the applicable shared constraints are satisfied.

### Preserve real sessions during admin preview

Use the admin's author-linked preview user only within authorized section-preview requests. Keep the authenticated author and any real learner login unchanged. Do not reuse `UserAuth.auto_enroll_admin/2`'s browser-session token substitution or the hidden-user login in `ProductsController.preview_launch/2` for the affected admin preview entries.

Resolve the preview user after actual-admin authorization and before controller/LiveView delivery loads enrollment, page state, or attempts. Carry the validated section-preview context through both perspectives, navigation, and activity/adaptive requests. The context must identify preview requests independently of the shared browser login, including when the admin has a real learner tab in that same section. Reuse existing signing and delivery setup where suitable; the exact transport and helper structure remain provisional. The URL family still selects presentation.

- **Acceptance:** With an ordinary learner tab open, enter admin preview of the same section, switch perspectives, and interact in both tabs. Each uses its intended user and saved progress. Entering or leaving preview does not change the learner login or actual-author authentication.
- **Acceptance:** Admin previews of two sections can remain open together without replacing each other's context. Refresh/reconnect preserves valid preview identity; stale, forged, reset, or revoked contexts are rejected instead of falling back to a real learner or shared hidden user. Verify this independently of the later project-preview Story.
