## Description

**Figma frames / prototype:** [Figma](https://www.figma.com/design/S8qAFhjjlnRyTHCg2Dyb8p/User-Preview-Overhaul?node-id=484-13119&t=5eBSflw0qUqbFcPl-1)

### User Need

As an author, I want to preview an individual activity bank question as students will see it, so that I can check its appearance before using it in a course page.

### Acceptance Criteria

**Successful behavior**

- Add a secondary **Preview** button to each activity bank question.
- Selecting **Preview** opens the selected question in a standalone preview, without surrounding course content or page elements.
- Render the question using the current student UI styling.
- Display the preview banner
- Keep the banner and exit control visible as the author scrolls.
- Exiting preview returns the author to the activity bank, preserving their search, filters, and position in the question list.
- Update the following actions to use design-system components with consistent styling, labels, and interaction states:
  - **Edit**
  - **Copy**
  - **View revision**
  - **Edit title**

**Exceptions and safeguards**

- Opening or exiting preview does not modify the question.
- Preview displays the selected question without requiring it to be added to a course page.
- Updating the existing action controls preserves their functionality and permissions.

### Accessibility Requirements

- **Keyboard:** Preview and all updated actions must be keyboard operable, follow a logical focus order, and have visible focus indicators.
- **Semantics and labels:** Use semantic buttons for actions and links for navigation. Give each control a descriptive accessible name; where actions repeat, associate them with the relevant question. Icon-only controls must have accessible names, and decorative icons must be hidden from assistive technology.
- **Focus:** On entering preview, move focus to a logical starting point that identifies the question-preview context. On exit, restore focus to the selected question’s **Preview** button.
- **Reflow and visibility:** Keep action controls and the preview exit control usable at increased zoom and narrow viewport widths. Ensure the sticky banner does not obscure content or focused elements.

### Single-question preview implementation

Let an author preview one working bank question in isolation, then resume the same bank list with its state and focus intact.

- **Scope:**
  - Add a secondary, question-specific Preview action and an authorized standalone Question Preview surface.
  - Render only the selected question with student styling and a sticky exit banner, preserving supported preview evaluation, hints, and reset.
  - Keep the originating bank mounted so search, filters, paging, and list position survive. Return focus to the selected question’s Preview action; use a safe bank destination if the opener is gone.
  - Do not edit the question, place it on a course page, or create a delivery section or learner attempt.
- **Technical approach:** Resolve the bank question from the project’s working publication under existing author authorization. Use a transient one-activity render model with the existing author-preview renderer and bridge, opening a separate preview window/tab while retaining the original bank state. Proposed implementation details are provisional; required behavior and binding constraints remain mandatory.
- **Acceptance criteria:**
  - **Positive:**
    - P1 — Every bank question has a secondary, keyboard-accessible Preview action named for that question.
    - P2 — It opens only the chosen working question, in student presentation under Question Preview, with a usable sticky exit at narrow widths and zoom.
    - P3 — Exit restores bank search, filters, paging/list position, and focus on the originating question's Preview action.
    - P4 — Supported author-preview interactions work through the existing preview bridge.
  - **Negative:**
    - N1 — Launch and interaction do not edit the question, add it to a course page, or create a delivery section/learner attempt.
    - N2 — A forged project/question URL cannot expose another project's or unauthorized question content; a missing question yields the existing safe not-found behavior.
    - N3 — The isolated surface contains no other bank questions, instructor preview cards/answer-key controls, or course navigation.
    - N4 — Unsupported activity behavior does not gain new capabilities under this Story.
- **Feature flags:** None.

#### Implementation guidance

- **Scope analysis:** Add the bank entry control and an authorized single-question preview surface using the working question revision. Preserve the originating bank state and question data. Reuse activity rendering and author-preview interaction mechanisms; do not create a temporary persisted course page, section, or learner attempt to host the question.
- **Sources and design:** [Design Handoff](https://docs.google.com/document/d/1XrwiN86AETdRxxyoGanQE2pAvl484RHPM6w0prWKk6c/edit); [bank controls](https://www.figma.com/design/S8qAFhjjlnRyTHCg2Dyb8p/User-Preview-Overhaul?node-id=534-12632); [standalone question](https://www.figma.com/design/S8qAFhjjlnRyTHCg2Dyb8p/User-Preview-Overhaul?node-id=484-13190). Figma-backed implementation uses the repository UI workflow. The Make prototype remains outside accepted evidence.
- **Analysis:**
  - **Existing behavior:** `assets/src/apps/bank/ActivityBank.tsx#createActivityEditors` renders `InlineActivityEditor` with an Edit toolbar item, duplicate/delete actions, tags, and objectives. `assets/src/components/activity/InlineActivityEditor.tsx` always creates the activity's authoring element; `editmode=false` is still authoring presentation. Bank filter logic, paging, and activity contexts are held in React state. `lib/oli/authoring/editing/activity_bank.ex#query/4` already authorizes project access and queries the working publication.
  - **Remaining gap:** The bank list has no per-question Preview control and no isolated Question Preview shell. The existing `ActivityBankController.preview/2` takes section, page revision, and selection IDs and renders a selection through authoring components; it is not an author-bank single-question preview implementation to reuse. `lib/oli_web/router.ex` exposes the bank index and query endpoints but no author-bank single-question preview endpoint.
  - **Reusable foundations:** `lib/oli/authoring/editing/page_editor.ex#render_page_html/4` builds author-preview activity summaries from the working publication, including transformed models and preview state. `lib/oli/rendering/activity/html.ex` selects the delivery element for author-preview mode. `assets/src/phoenix/activity_bridge.ts#initPreviewActivityBridge` handles preview evaluation/reset/hints without persisting question edits. These are reusable rendering mechanisms, not an already complete bank preview flow.
  - **Verification:** Code and existing tests were read; none was run. `test/oli_web/live/workspaces/course_author/activity_bank_live_test.exs` covers login/project authorization, script loading, and excluded LTI registrations. `test/oli_web/controllers/activity_bank_controller_test.exs` covers bank index/revision-history permissions. Neither establishes the new isolated flow. Child design must confirm how a one-reference render context supplies activity-specific context, script registration, and bibliography. Browser verification must cover the existing list state and focus after exit.
- **Technical analysis:** Add a project-authorized read endpoint for a bank question and resolve its current revision within the project's working publication. Build a transient one-activity content model for the existing author-preview rendering functions and bridge; validate that the referenced resource is an allowed bank question. Render only that question inside a Question Preview shell. Launch it from the bank in a separate window/tab while the original React list remains mounted, following the existing authoring preview launch pattern. Keep a stable question-specific opener target and restore focus on exit; handle a missing opener with a safe bank destination. This approach preserves the in-memory filter/paging/list state without inventing a new persistence store. [F-004](https://eliterate.atlassian.net/browse/MER-6214)'s page shell is a visual reference, not a hard dependency; reuse a small shared banner only if its existing shape fits both contexts.
- **Integration requirements:** None. Existing author-preview rendering and activity scripts are available. Exit handoff to [T-010](https://eliterate.atlassian.net/browse/MER-6231): the bank Preview action and its state/focus contract.
- **Sizing analysis:** L. The missing endpoint/context and shell must integrate with the existing renderer and bank React state; the renderer itself does not need replacement.
