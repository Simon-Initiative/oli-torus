## Description

**Figma frames / prototype:** [Figma](https://www.figma.com/design/S8qAFhjjlnRyTHCg2Dyb8p/User-Preview-Overhaul?node-id=484-13119&t=5eBSflw0qUqbFcPl-1)

### User Need

As an author, I want to preview an individual activity bank question as students will see it, so that I can check its appearance before using it in a course page.

### Acceptance Criteria

**Successful behavior**

- Add a secondary **Preview** button to each activity bank question.
- Selecting **Preview** opens the selected question in a standalone preview, without surrounding course content or page elements.
- Render the question using the current student UI styling.
- Display the preview banner
- Keep the banner and exit control visible as the author scrolls.
- Exiting preview returns the author to the activity bank, preserving their search, filters, and position in the question list.
- Update the following actions to use design-system components with consistent styling, labels, and interaction states:
  - **Edit**
  - **Copy**
  - **View revision**
  - **Edit title**

**Exceptions and safeguards**

- Opening or exiting preview does not modify the question.
- Preview displays the selected question without requiring it to be added to a course page.
- Updating the existing action controls preserves their functionality and permissions.

### Accessibility Requirements

- **Keyboard:** Preview and all updated actions must be keyboard operable, follow a logical focus order, and have visible focus indicators.
- **Semantics and labels:** Use semantic buttons for actions and links for navigation. Give each control a descriptive accessible name; where actions repeat, associate them with the relevant question. Icon-only controls must have accessible names, and decorative icons must be hidden from assistive technology.
- **Focus:** On entering preview, move focus to a logical starting point that identifies the question-preview context. On exit, restore focus to the selected question’s **Preview** button.
- **Reflow and visibility:** Keep action controls and the preview exit control usable at increased zoom and narrow viewport widths. Ensure the sticky banner does not obscure content or focused elements.

## Technical Guidance

### Suggested approach

Resolve one bank question from the project's working publication under existing author authorization, then render it with the author-preview activity renderer and bridge. Use a transient one-activity model; do not persist a temporary page, section, or learner attempt.

Open the Question Preview in a separate window/tab while the React bank remains mounted. This preserves search, filters, paging, and list position without new state storage. On exit, restore focus to that question's Preview action; if the opener is gone, use a safe bank destination. The shell contains only the selected question, student styling, and the sticky preview banner/exit—not course navigation, instructor cards, or answer-key controls.

### Existing code

- `assets/src/apps/bank/ActivityBank.tsx#createActivityEditors` builds the bank controls and holds list state. `InlineActivityEditor.tsx` renders authoring components even with `editmode=false`; that is not a student preview.
- `lib/oli/authoring/editing/activity_bank.ex#query/4` supplies working-publication/project-access logic. The existing `ActivityBankController.preview/2` previews a delivery selection, not one author-bank question; a project-authorized single-question entry is needed.
- `PageEditor.render_page_html/4`, `lib/oli/rendering/activity/html.ex`, and `initPreviewActivityBridge` in `assets/src/phoenix/activity_bridge.ts` provide reusable rendering, evaluation, hints, and reset. Supply the selected activity's context, scripts, and bibliography.

### Checks and limits

Verify authorized, denied, forged project/question, and missing-question cases; preserve safe not-found behavior. Launch/interaction must not edit the question or create delivery records. Keep supported preview interactions without adding unsupported activity capabilities. Verify entry/exit focus, bank-state restoration, scrolling, and reflow in the browser.

Existing authorization tests are in `activity_bank_live_test.exs` and `activity_bank_controller_test.exs`; they do not cover the new isolated flow. For action styling, preserve edit locks, copy, admin-only revision history, title save/cancel, and Delete. Scope changes to bank controls rather than all inline editors. Button labels use the handoff's Title Case guidance.

The sub-tasks separate rendering, launch/shell, and action styling. Reuse a small shared banner if suitable; a dependency on the author-page-preview redesign is not required.

Existing test references: `test/oli_web/live/workspaces/course_author/activity_bank_live_test.exs`, `test/oli_web/controllers/activity_bank_controller_test.exs`.
