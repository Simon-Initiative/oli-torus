# S-011: Align bank question action controls

- **Status:** Created and verified
- **Qualification:** Qualified. Existing bank controls demonstrably use inconsistent Bootstrap/icon presentation and generic accessible naming. Their operations and permission rules already exist.
- **Lane:** C, second.
- **Ticket:** [MER-6198](https://eliterate.atlassian.net/browse/MER-6198)

## Description

Align the bank’s question actions with the design system while preserving their existing operations, locks, and permissions.

- **Requirements:** [MER-6158](https://eliterate.atlassian.net/browse/MER-6158), R-005, R-008. Full requirements are in the epic ticket.
- **Scope:**
  - Update Preview, Edit, Copy, View revision, and Edit title controls, keeping Preview secondary.
  - Give repeated controls question-specific accessible names, visible keyboard focus, and decorative icons hidden from assistive technology.
  - Preserve edit locks, copy behavior, admin-only revision history, title save/cancel, and Delete. Keep broader bank/filter redesign and unrelated inline editors outside scope.
- **Technical approach:** Adapt the existing bank toolbar and pass question identity into its accessible names. Reuse existing handlers and guards, scoping shared inline-editor or title-editor presentation changes to bank usage. Proposed implementation details are provisional; required behavior and binding constraints remain mandatory.
- **Acceptance criteria:**
  - **Positive:**
    - P1 — Preview remains secondary; Edit, Copy, View revision, and Edit title match the bank design and approved casing.
    - P2 — Each repeated control names its question and has visible keyboard focus.
    - P3 — Edit/Done still acquires/releases the existing lock, Copy creates the same kind of banked question, permitted revision history opens the same route, and title edits save/cancel as before.
  - **Negative:**
    - N1 — Decorative icons do not add redundant accessible names.
    - N2 — Non-admin authors do not gain revision-history access, and restyling does not bypass edit locks or persistence validation.
    - N3 — Broader bank filters/editor layout and non-bank inline editor behavior are not changed by bank-specific styling.
    - N4 — Preview continues to satisfy S-010's isolation and return-state contract.
- **Prerequisites:** S-010.
- **Size:** M.
- **Feature flags:** None.

## Local analysis

- **Requirements analysis:** [R-005](docs/exec-plans/current/epics/user-preview/epic.md#r-005-preview-a-bank-question-in-isolation) requires consistent Preview, Edit, Copy, View revision, and Edit title controls; repeated controls identify the question and decorative icons are hidden from assistive technology. [R-008](docs/exec-plans/current/epics/user-preview/epic.md#r-008-keep-preview-controls-accessible-and-authorized) requires keyboard operation and visible focus. Q5 excludes broader question-editor/filter redesign and Q7 supplies sentence casing.
- **Scope analysis:** Update only the named bank action surface and necessary title-edit affordance. Preserve edit locks, duplicate behavior, admin-only revision history visibility, and title persistence. Retain existing Delete behavior and keep unrelated inline editors, bank filters, tags, and objectives outside the styling change.
- **Sources and design:** [Design Handoff](https://docs.google.com/document/d/1XrwiN86AETdRxxyoGanQE2pAvl484RHPM6w0prWKk6c/edit); [bank controls](https://www.figma.com/design/S8qAFhjjlnRyTHCg2Dyb8p/User-Preview-Overhaul?node-id=534-12632). Detailed component mapping belongs to the repository UI workflow during child implementation.
- **Analysis:**
  - **Existing behavior:** `assets/src/apps/bank/EditButton.tsx` renders Bootstrap Edit/Done buttons with lock/check icons and no question-specific name. `assets/src/components/activity/InlineActivityEditor.tsx` renders a duplicate icon button with the generic title “Duplicate this question,” a View revision history link gated by `revisionHistoryLink`, and the title through shared `TextEditor`. `ActivityBank.tsx#onChangeEditing` already controls edit locking; `onDuplicateActivity` already uses `createCopy`.
  - **Remaining gap:** The visible controls do not match the required design-system presentation or sentence-cased labels, and repeated controls do not identify their question. Decorative icons in these controls lack explicit assistive-technology exclusion. These are bounded UI changes; no new edit, copy, history, or title service is justified.
  - **Verification and uncertainty:** Code and bank controller/LiveView tests were read, not executed. `test/oli_web/controllers/activity_bank_controller_test.exs` explicitly checks that revision history is visible for admins and absent for other authors. The shared inline editor and `assets/src/components/TextEditor.tsx` are used outside the bank; child design must choose bank-scoped props/wrappers to avoid changing unrelated surfaces. Actual visual/focus behavior needs browser verification against the accepted frame.
- **Technical analysis:** Pass question identity/title into the bank toolbar controls so their accessible names identify the target. Use existing design-system button styles for the five named actions, preserving current handlers and conditions. Scope any shared `InlineActivityEditor` or `TextEditor` option to bank usage; do not globally restyle every inline activity editor. Keep the edit lock transition, Copy creation callback, revision-history route and admin guard, and title update callback. Hide decorative icons from the accessibility tree and verify focus through Edit/Done and title-save/cancel transitions.
- **Prerequisite handoffs:** S-010's Preview control is available for alignment and regression checking. The existing four actions can be styled independently, but final acceptance of all five actions requires that control.
- **Sizing analysis:** M. The shared title/inline-editor boundary and required naming/focus behavior require bank-scoped changes and regression checks; no backend service work is included.
