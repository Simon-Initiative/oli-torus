### User Need

As an instructor, I want contextual explanations of student-facing features and special cases in student preview, so that I can understand how students will experience the course and recognize any instructor-only controls.

### Acceptance Criteria

**Successful behavior**

- Student preview displays an **Instructor preview note** beside relevant bank-selected questions to explain student-facing behavior or instructor-only controls.
- Each note is clearly labeled **Instructor preview** note and appears next to the content or control it explains.
- Notes explain the relevant behavior and distinguish what students experience from what is available only to instructors.
- **Activity bank selection questions:** Explain how the question shown in preview relates to the selection students receive and identify any instructor-only controls.

**Exceptions and safeguards**

- Instructor preview notes and associated instructor-only controls are never displayed to students.
- Notes appear only where relevant and do not replace or obscure student-facing content.
- Explanatory notes do not receive keyboard focus **unless** they contain an interactive element.

### Accessibility Requirements

- **Structure and labels:** Include the visible text Instructor preview note and programmatically associate it with the note content.
- **Reading order:** Place each note in a logical reading order next to the content it explains.
- **Keyboard and focus:** Any actions within a note must be keyboard operable, have descriptive accessible names, and show visible focus. Follow a logical focus order without moving focus automatically to static notes.
- **Assistive technology:** Static notes must be available through normal screen-reader navigation without alert announcements. Student-facing views must exclude instructor preview notes and controls from both the visible interface and the accessibility tree.

## Technical Guidance

### Size and feasibility

- **Size:** M (3–5 focused engineering days).
- **Single-engineer feasibility:** Good individual assignment. Selection provenance already exists; the main work is accessible presentation and eligibility across controller and LiveView rendering.
- **Estimate basis:** An engineer familiar with Torus; includes implementation and verification, excludes dependency/review waiting time. This is a planning estimate, not a delivery commitment. Story effort includes any sub-tasks; do not add the Story and sub-task estimates together.

### Work and ownership

Deliver the reusable Instructor preview note presentation and show it beside bank-selected questions in authorized instructor/admin Student Preview. [MER-6213](https://eliterate.atlassian.net/browse/MER-6213) owns the gating messages and actions that use this presentation. This Story can finish before gating integration.

Keep the shared note small: a visible/programmatic label, explanation content, and optional accessible actions. Gate evaluation and permission checks stay with callers. Static notes follow reading order without taking focus or announcing as alerts; any actions retain descriptive names and visible focus.

### Existing code and suggested approach

`ActivityProvider.replace_with_reference/2` in `lib/oli/delivery/activity_provider.ex` already adds `source-selection` to realized bank questions. Use that metadata in `Oli.Rendering.Activity.Html.activity/2` to place the note. Supply server-validated instructor/admin eligibility through both `Student.Utils.build_html/3` and controller rendering contexts. An ordinary delivery URL or a false presentation flag does not identify an actual learner versus an authorized preview.

`ActivityBankSelectionPreview.tsx` is the Instructor View sample/management card. Changing only that card would miss Student Preview. Keep its management actions in Instructor View; do not add Manage questions or customization controls to Student Preview. Header suppression and back/focus restoration are already owned by [MER-6224](https://eliterate.atlassian.net/browse/MER-6224).

### Checks

- Verify nearby notes for multi-question selections in LiveView and controller delivery. Preserve normal interaction and persisted selections.
- Exclude notes from unrelated content, actual learner markup/accessibility trees, and separate author-preview contexts.
- Test shared label/text/action behavior independently of gating integration. Reuse `test/oli/delivery/activity_provider_test.exs` for selection provenance coverage.

Design evidence: [bank-selection note](https://www.figma.com/design/S8qAFhjjlnRyTHCg2Dyb8p/User-Preview-Overhaul?node-id=529-11932) shows the note in Student Preview without management controls. Use existing rendering/components; no new selection engine or provenance storage is needed.
