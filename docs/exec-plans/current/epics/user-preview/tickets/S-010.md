# S-010: Preview one bank question without changing it

- **Status:** Created and verified
- **Qualification:** Qualified. The bank already renders questions through read-only authoring components, but it has no per-question isolated student-style Preview action or standalone author-bank preview route.
- **Lane:** C, first.
- **Ticket:** [MER-6195](https://eliterate.atlassian.net/browse/MER-6195)

- **Sub-task tickets:** S-010a = [MER-6196](https://eliterate.atlassian.net/browse/MER-6196); S-010b = [MER-6197](https://eliterate.atlassian.net/browse/MER-6197)
## Description

Let an author preview one working bank question in isolation, then resume the same bank list with its state and focus intact.

- **Requirements:** [MER-6158](https://eliterate.atlassian.net/browse/MER-6158), R-005, R-008. Full requirements are in the epic ticket.
- **Scope:**
  - Add a secondary, question-specific Preview action and an authorized standalone Question Preview surface.
  - Render only the selected question with student styling and a sticky exit banner, preserving supported preview evaluation, hints, and reset.
  - Keep the originating bank mounted so search, filters, paging, and list position survive. Return focus to the selected question’s Preview action; use a safe bank destination if the opener is gone.
  - Do not edit the question, place it on a course page, or create a delivery section or learner attempt.
- **Technical approach:** Resolve the bank question from the project’s working publication under existing author authorization. Use a transient one-activity render model with the existing author-preview renderer and bridge, opening a separate preview window/tab while retaining the original bank state. Proposed implementation details are provisional; required behavior and binding constraints remain mandatory.
- **Acceptance criteria:**
  - **Positive:**
    - P1 — Every bank question has a secondary, keyboard-accessible Preview action named for that question.
    - P2 — It opens only the chosen working question, in student presentation under Question Preview, with a usable sticky exit at narrow widths and zoom.
    - P3 — Exit restores bank search, filters, paging/list position, and focus on the originating question's Preview action.
    - P4 — Supported author-preview interactions work through the existing preview bridge.
  - **Negative:**
    - N1 — Launch and interaction do not edit the question, add it to a course page, or create a delivery section/learner attempt.
    - N2 — A forged project/question URL cannot expose another project's or unauthorized question content; a missing question yields the existing safe not-found behavior.
    - N3 — The isolated surface contains no other bank questions, instructor preview cards/answer-key controls, or course navigation.
    - N4 — Unsupported activity behavior does not gain new capabilities under this Story.
- **Prerequisites:** None.
- **Size:** L.
- **Sub-tasks (in order; both required for Story acceptance):**
  - **S-010a — Authorized single-question rendering.** Resolve the working bank question under project authorization and render one activity with author-preview state/bridge. Verify allowed, denied, missing, and no-write cases.
  - **S-010b — Bank launch, banner, and return.** Add the secondary Preview control and Question Preview shell/exit. Verify interaction, list-state preservation, focus restoration, and responsive layout.
- **Feature flags:** None.

- **Scope analysis:** Add the bank entry control and an authorized single-question preview surface using the working question revision. Preserve the originating bank state and question data. Reuse activity rendering and author-preview interaction mechanisms; do not create a temporary persisted course page, section, or learner attempt to host the question.

- **Analysis:**

Bank filter logic, paging, and activity contexts are held in React state. `lib/oli/authoring/editing/activity_bank.ex#query/4` already authorizes project access and queries the working publication.

  - **Reusable foundations:** `lib/oli/authoring/editing/page_editor.ex#render_page_html/4` builds author-preview activity summaries from the working publication, including transformed models and preview state. `lib/oli/rendering/activity/html.ex` selects the delivery element for author-preview mode. `assets/src/phoenix/activity_bridge.ts#initPreviewActivityBridge` handles preview evaluation/reset/hints without persisting question edits. These are reusable rendering mechanisms, not an already complete bank preview flow.
  - **Verification and uncertainty:** Code and existing tests were read; none was run. `test/oli_web/live/workspaces/course_author/activity_bank_live_test.exs` covers login/project authorization, script loading, and excluded LTI registrations. `test/oli_web/controllers/activity_bank_controller_test.exs` covers bank index/revision-history permissions. Neither establishes the new isolated flow. Child design must confirm how a one-reference render context supplies activity-specific context, script registration, and bibliography. Browser verification must cover the existing list state and focus after exit.
- **Technical analysis:** Add a project-authorized read endpoint for a bank question and resolve its current revision within the project's working publication. Build a transient one-activity content model for the existing author-preview rendering functions and bridge; validate that the referenced resource is an allowed bank question. Render only that question inside a Question Preview shell. Launch it from the bank in a separate window/tab while the original React list remains mounted, following the existing authoring preview launch pattern. Keep a stable question-specific opener target and restore focus on exit; handle a missing opener with a safe bank destination. This approach preserves the in-memory filter/paging/list state without inventing a new persistence store. S-007's page shell is a visual reference, not a hard dependency; reuse a small shared banner only if its existing shape fits both contexts.
- **Prerequisite handoffs:** None. Existing author-preview rendering and activity scripts are available. Exit handoff to S-011: the bank Preview action and its state/focus contract.
- **Sizing analysis:** L. The missing endpoint/context and shell must integrate with the existing renderer and bank React state; the renderer itself does not need replacement.
