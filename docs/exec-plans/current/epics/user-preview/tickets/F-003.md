## Description

**Figma frames / prototype:** [Figma](https://www.figma.com/design/S8qAFhjjlnRyTHCg2Dyb8p/User-Preview-Overhaul?node-id=484-15711&t=5eBSflw0qUqbFcPl-1)

### User Need

As an instructor, I want to preview content behind student gating restrictions while understanding what students see when access is restricted, so that I can review the page and verify its access conditions. I also need direct access to the settings that control those conditions.

### Acceptance Criteria

**Successful behavior**

- When student preview displays a page restricted by gating conditions:
  - Show the student-facing restriction message.
  - Display an **Instructor preview note** explaining that gating conditions restrict access to the page.
  - Include a **Preview page** button in the note.
- Selecting **Preview page** displays the page’s content in student preview in place of the restriction message.
- While the content is displayed, retain the instructor preview note, explain that restrictions are being bypassed for preview, and replace **Preview page** with **Show restricted view.**
- Selecting **Show restricted view** restores the student-facing restriction message and the original note with the **Preview page** button.
- In instructor view, a page with gating conditions displays an informational banner identifying that conditions are applied, with links to **Assessment settings** and the **Advanced gating tool.**

**Exceptions and safeguards**

- Bypassing restrictions applies only to the instructor’s preview. It does not change gating settings or grant students access.
- Previewing the content does not mark gating prerequisites as completed.
- Instructor preview notes and bypass controls are never available to students.

### Accessibility Requirements

- **Keyboard:** Both preview actions and the settings links must be keyboard operable, appear in a logical focus order, and have visible focus indicators.
- **Semantics and labels:** Use semantic buttons for preview actions and links for navigation to settings. Programmatically associate the instructor preview note’s label with its content, and identify restrictions through text rather than color or icons alone.
- **Focus:** Keep focus on the toggle control as its label changes between Preview page and Show restricted view. Ensure content hidden by either state contains no focusable elements.
- **Assistive technology:** Announce when restricted content is displayed or the restricted view is restored, without reading the entire page. Keep the note and banner available in the normal reading order; static explanatory content should not use an alert role.

## Technical Guidance

### Suggested approach

Use the shared note presentation from [MER-6212](https://eliterate.atlassian.net/browse/MER-6212). This Story owns the gating-specific explanation, Preview Page / Show Restricted View actions, focus retention, and state announcements. Do not duplicate the note's label/styling or bank-note work.

Reuse `Oli.Delivery.Gating.blocked_by/3` and `details/2`. Keep the calculated restriction separate from whether the instructor has temporarily revealed the content. Revealing it changes display only, not gate configuration, student exceptions, or prerequisite completion.

### Code to inspect

`lib/oli_web/live_session_plugs/init_page.ex`, `lib/oli/delivery/page/prologue_state.ex`, and `lib/oli_web/plugs/maybe_gated_resource.ex` currently bypass gates for admins. Student Preview must still calculate and show their restriction details. Cover basic, graded, adaptive, LiveView, and controller entry; changing only the basic lesson view is insufficient. Reuse the existing Assessment settings and Advanced gating tool destinations for the Instructor View banner.

### Checks

- Test restricted → revealed → restricted behavior for instructors and admins, including retained toggle focus, state announcements, and no focusable elements in hidden content.
- Actual learners cannot see or invoke preview bypass. Enforce this server-side.
- Bypass does not change student access or prerequisite completion. Normal preview visits and activity interactions retain existing persistence; do not introduce temporary attempt storage or automatic reset.
