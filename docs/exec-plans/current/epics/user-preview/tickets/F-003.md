## ⭐ Feature: Gating Instructor View/Student Preview Bypass

**Figma frames / prototype:** [Figma](https://www.figma.com/design/S8qAFhjjlnRyTHCg2Dyb8p/User-Preview-Overhaul?node-id=484-15711&t=5eBSflw0qUqbFcPl-1)
**Readiness:** Ready for ticketing

### User Need

As an instructor, I want to preview content behind student gating restrictions while understanding what students see when access is restricted, so that I can review the page and verify its access conditions. I also need direct access to the settings that control those conditions.

### Acceptance Criteria

**Successful behavior**

- When student preview displays a page restricted by gating conditions:
  - Show the student-facing restriction message.
  - Display an **Instructor preview note** explaining that gating conditions restrict access to the page.
  - Include a **Preview page** button in the note.
- Selecting **Preview page** displays the page’s content in student preview in place of the restriction message.
- While the content is displayed, retain the instructor preview note, explain that restrictions are being bypassed for preview, and replace **Preview page** with **Show restricted view.**
- Selecting **Show restricted view** restores the student-facing restriction message and the original note with the **Preview page** button.
- In instructor view, a page with gating conditions displays an informational banner identifying that conditions are applied, with links to **Assessment settings** and the **Advanced gating tool.**

**Exceptions and safeguards**

- Bypassing restrictions applies only to the instructor’s preview. It does not change gating settings or grant students access.
- Previewing the content does not mark gating prerequisites as completed.
- Instructor preview notes and bypass controls are never available to students.

### Accessibility Requirements

- **Keyboard:** Both preview actions and the settings links must be keyboard operable, appear in a logical focus order, and have visible focus indicators.
- **Semantics and labels:** Use semantic buttons for preview actions and links for navigation to settings. Programmatically associate the instructor preview note’s label with its content, and identify restrictions through text rather than color or icons alone.
- **Focus:** Keep focus on the toggle control as its label changes between Preview page and Show restricted view. Ensure content hidden by either state contains no focusable elements.
- **Assistive technology:** Announce when restricted content is displayed or the restricted view is restored, without reading the entire page. Keep the note and banner available in the normal reading order; static explanatory content should not use an alert role.

## Technical Guidance

This section migrates the implementation guidance of `S-004` / `MER-6185`.

### Migrated delivery contract

Let an authorized instructor or admin reveal a gated page in Student Preview and restore its restricted view without changing student access.

- **Requirements:** [MER-6158](https://eliterate.atlassian.net/browse/MER-6158), R-003, R-008. The feature requirements are in the owning replacement Story; requirement IDs remain reference identifiers in the repository epic.
- **Scope:**
  - Show the restriction message, Instructor preview note, and Preview Page / Show Restricted View control, including for admins whose normal access bypasses gates.
  - Show the existing Assessment settings and Advanced gating tool links in Instructor View.
  - Keep focus and announcements correct; the reveal action changes no gate settings, exceptions, student access, or prerequisite completion. Normal preview interactions retain existing persistence.
- **Technical approach:** Reuse the gate evaluator and restriction details, keeping the restriction result separate from local revealed/hidden presentation. Apply the authorized preview behavior across relevant LiveView and controller paths; do not introduce temporary attempt storage. Proposed implementation details are provisional; required behavior and binding constraints remain mandatory.
- **Acceptance criteria:**
  - **Positive:**
    - AC1: A restricted preview shows the student message, Instructor preview note and Preview Page action for the authorized actor, including admin.
    - AC2: Preview Page reveals content and changes to Show Restricted View; the latter restores the same restriction.
    - AC3: Toggle focus is retained, state changes are announced, and hidden content cannot hold focus.
    - AC4: Instructor View displays informational links to Assessment settings and Advanced gating tool.
  - **Negative:**
    - AC5: Ordinary students cannot see or invoke the local bypass.
    - AC6: Using the bypass changes no gating settings, student access, exceptions or prerequisite-completion state.
    - AC7: Normal persistent preview visits and interactions follow Q9; this Story adds neither automatic reset nor temporary progress storage.
- **Size:** L.
- **Feature flags:** None.

### Supporting technical analysis

- **Requirements analysis:** [R-003](docs/exec-plans/current/epics/user-preview/tickets/F-003.md): restriction message plus Instructor preview note, Preview Page / Show Restricted View toggle, focus and announcement, Instructor View links to Assessment settings and Advanced gating tool, and no changes to student access/gating/prerequisite completion. [R-008](docs/exec-plans/current/epics/user-preview/tickets/F-009.md): keyboard, focus, authorized bypass. Q9 retains normal Student Preview attempt/progress persistence.
- **Scope analysis:** Add the local presentation bypass and explanatory banner across applicable basic/graded/adaptive entry paths. Evaluate restriction information for previewing admins instead of silently losing it through existing admin bypass. Do not change gating configuration or mark prerequisites complete; normal delivery interactions retain Q9 behavior.
- **Sources and design:** [Design Handoff](https://docs.google.com/document/d/1XrwiN86AETdRxxyoGanQE2pAvl484RHPM6w0prWKk6c/edit); [restricted](https://www.figma.com/design/S8qAFhjjlnRyTHCg2Dyb8p/User-Preview-Overhaul?node-id=484-15826); [bypassed](https://www.figma.com/design/S8qAFhjjlnRyTHCg2Dyb8p/User-Preview-Overhaul?node-id=529-11932); [instructor](https://www.figma.com/design/S8qAFhjjlnRyTHCg2Dyb8p/User-Preview-Overhaul?node-id=484-15942).
- **Analysis:**
  - **Existing behavior:** `Oli.Delivery.Gating.blocked_by/3` and `details/2` already evaluate and explain restrictions. `lib/oli_web/live_session_plugs/init_page.ex`, `lib/oli/delivery/page/prologue_state.ex`, and `lib/oli_web/plugs/maybe_gated_resource.ex` each bypass gates for admins. `InitPage` creates persistent page context before computing its blocking-gate display. Basic `PreviewPageContext` renders instructor content without learner setup.
  - **Remaining gap:** No approved Preview Page / Show Restricted View toggle or settings banner is present in the instructor page component. Existing admin bypass skips the restriction details that Student Preview must show. A change only in the basic LiveView would omit graded/adaptive/controller entry paths.
  - **Verification and uncertainty:** Static inspection only; no runtime checks. R-003 protects gates, student access, and prerequisite completion from bypass mutations. Q9 retains normal persistent preview visits and subsequent interactions; the toggle does not introduce a separate no-progress/no-grade policy. Child design must define the smallest way to retain restriction details while allowing authorized local presentation.
- **Technical analysis:** Reuse the gate evaluator and detail formatter. Within [T-002](docs/exec-plans/current/epics/user-preview/tickets/T-002.md)’s authorized preview context, compute the student restriction presentation even for admins and retain that result separately from the local revealed/hidden state. Add the two-state control with focus and announcement behavior, and render Instructor View’s links to the existing settings destinations. Apply the selected presentation at the appropriate live/controller boundary so a bypass never changes a gate record, student exception, or completion record. Avoid creating a temporary attempt subsystem; gate-free Student Preview still uses normal delivery persistence.
- **Prerequisite handoffs:** [T-002](docs/exec-plans/current/epics/user-preview/tickets/T-002.md)’s authorized presentation context and [T-003](docs/exec-plans/current/epics/user-preview/tickets/T-003.md)’s usable perspective entry. [T-001](docs/exec-plans/current/epics/user-preview/tickets/T-001.md) supplies the Instructor View links. Exit handoff: both restricted and revealed states are usable with existing delivery content.
- **Sizing analysis:** L; multiple gating boundaries and admin bypass semantics make this broader than a single banner/toggle change.
