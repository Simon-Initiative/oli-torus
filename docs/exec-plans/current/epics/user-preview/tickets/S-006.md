# S-006: Guide instructors to the perspective selector once

- **Status:** Created and verified
- **Qualification:** Qualified. User preference storage and a dismissal pattern exist, but the switcher callout and dedicated preference do not. Detailed frame placement remains a recorded child UI-analysis task.
- **Lane:** A, sixth.
- **Ticket:** [MER-6187](https://eliterate.atlassian.net/browse/MER-6187)

## Description

On first entry to Instructor View, highlight the perspective selector with “Switch between instructor view and student preview.” until explicitly dismissed.

- **Requirements:** [MER-6158](https://eliterate.atlassian.net/browse/MER-6158), R-009, R-008. Full requirements are in the epic ticket.
- **Scope:**
  - Keep the selector usable and provide an accessible dismiss control and Escape behavior within the callout.
  - Store dismissal on the current instructor/user preference record, including the generated admin preview user. Reuse that preference across courses, sessions, and devices for the same user.
  - Preserve visible focus and screen-reader access. Do not store a preference on author accounts or show guidance in selection management and author previews.
- **Technical approach:** Add the dedicated default-false preference to the existing user preference infrastructure and render the callout beside S-003’s selector. Persist only successful explicit dismissal, handle failed/stale reads, and return focus to the selector when its focused dismiss control is removed. Proposed implementation details are provisional; required behavior and binding constraints remain mandatory.
- **Acceptance criteria:**
  - **Positive:**
    - AC1: First entry to Instructor View shows the exact R-009 message and selector highlight; the selector stays usable.
    - AC2: A keyboard-accessible “Dismiss preview guidance” control or Escape within the callout removes both elements.
    - AC3: Successful dismissal persists on the instructor/user record across courses, sessions and devices where that record is used. Admin previews reuse the same author-linked user across sections; Reset Preview User naturally gives its replacement default preferences.
    - AC4: Screen readers can read the message without automatic focus movement; focus stays visible and falls back to the selector when dismissal removes the focused control.
  - **Negative:**
    - AC5: Display alone does not save dismissal, failed writes are not treated as saved, and stale account reads do not re-show successfully dismissed guidance.
    - AC6: Guidance is absent in bank-selection management and author previews. No author-account preference or separate per-admin dismissal store is added; the generated user naturally owns its own preferences.
- **Prerequisites:** S-002, S-003.
- **Size:** M.
- **Feature flags:** None.

## Local analysis

- **Requirements analysis:** [R-009](docs/exec-plans/current/epics/user-preview/epic.md#r-009-guide-first-time-instructors-to-the-view-switcher): exact message “Switch between instructor view and student preview.”, highlighted usable dropdown, labeled dismiss control, explicit per-user dismissal, Escape within the callout, screen-reader availability and focus restoration. [R-008](docs/exec-plans/current/epics/user-preview/epic.md#r-008-keep-preview-controls-accessible-and-authorized): accessible interaction and reflow. Hide guidance in selection management and author previews.
- **Scope analysis:** Add a dedicated persisted guidance preference and callout on the S-003 selector surface. Reuse existing user preference infrastructure. Store dismissal on the instructor/current user record, including the dedicated admin preview user when active. Add no preference to author accounts.
- **Sources and design:** [Design Handoff](https://docs.google.com/document/d/1XrwiN86AETdRxxyoGanQE2pAvl484RHPM6w0prWKk6c/edit), Instructor Guidance on Switching Views criteria; [Instructor Interface](https://www.figma.com/design/S8qAFhjjlnRyTHCg2Dyb8p/User-Preview-Overhaul?node-id=484-14126) supplies the selector context. The exact guidance-frame placement is not available in the approved evidence and must be reviewed during child UI analysis; no prototype-only behavior is assumed.
- **Analysis:**
  - **Existing behavior:** `lib/oli/accounts.ex` supplies user preference get/set functions, and `lib/oli/accounts/schemas/user_preferences.ex` defines persisted embedded preference fields. `lib/oli_web/live/sections/assessment_settings/settings_live.ex` demonstrates an existing warning-dismissal pattern. The current preview header is a static label, and the user preference schema has no switcher-guidance dismissal field.
  - **Remaining gap:** The dedicated default-false user preference, callout/highlight, dismiss event, durable write, and focus behavior must be added after the selector exists. Dismissal remains a user preference; different generated user records naturally have different dismissal states.
  - **Verification and uncertainty:** Inspected the user preference schema/accessors and assessment warning behavior; no tests or browser checks run. Fetching a preference by user ID reads the latest record, while passing a previously loaded struct can be stale. Visual placement remains unverified under the approved evidence limitation. Preference ownership follows the current user supplied by the entry flow, including the admin preview identity supplied by S-016. Actual-actor authorization remains separate.
- **Technical analysis:** Add the dedicated field only to the user embedded preference changeset, defaulting to false for existing and new users. Use existing user preference get/set functions with the current user ID, including the dedicated admin preview user when active. Add no author preference or separate per-admin dismissal mapping. Render the exact message next to S-003’s selector without moving focus. A successful explicit dismiss removes the message/highlight and persists the preference; failed writes do not become durable dismissal. Escape only dismisses when focus is within the callout, and removing the focused dismiss control sends focus to the selector. Reuse the existing preference pattern rather than introducing an onboarding table or browser-only store.
- **Prerequisite handoffs:** S-003’s usable selector and stable focus trigger, with the current instructor user; S-016 supplies the generated admin identity when used. This does not make S-016 a prerequisite for the instructor callout work. S-005 is a lane scheduling predecessor, not a technical prerequisite for the preference/callout work.
- **Sizing analysis:** M; existing user preference infrastructure is reusable, while generated-user dismissal, persistence failure and accessible focus need verification.
