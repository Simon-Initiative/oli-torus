## Description

## Scope

Implement the author/admin-authorized Reset Preview operation and its failed-state action, replacing only the project’s failed managed preview section.

## Acceptance criteria

### Positive

- Authorized regular project authors and admins can reset a failed preview; the replacement uses the latest publication and is available through the normal readiness flow.
- The old section retains its preview marker for later queries; the UI explains fresh shared progress and that other open previews may need reopening.
- Reset failure preserves a recoverable previous association and exposes no partial replacement.

### Negative

- Unauthorized users, arbitrary section targets, ordinary delivery sections, reusable products/templates, and non-failed previews cannot use reset.
- Concurrent resets, Publish, and obsolete update jobs cannot corrupt the replacement association. Retired preview contexts are rejected even for admins.
- Actual accounts, other projects, and normal template sessions remain intact; no user deletion, explicit progress clearing, or cleanup process is introduced.

## Technical Guidance

Reuse section creation and retirement mechanisms. Recheck project access, failed readiness, and the managed association server-side under the existing authentication/CSRF patterns. Create a latest-publication replacement and atomically switch the association only after completion; retire the old section while preserving its marker. Supply the common action to MER-6236's LiveView with accessible success/failure feedback and the explanation of shared fresh progress. Section replacement naturally gives fresh progress; do not clear attempts explicitly.

Use the parent [F-007](https://eliterate.atlassian.net/browse/MER-6217) for shared feature requirements, design sources, and code evidence. This sub-task is complete when its scoped acceptance criteria above and the applicable shared constraints are satisfied.

### Recover when the update job is gone

Treat the launch check's stale/incomplete-with-no-applicable-live-job outcome as a failed preview eligible for Reset Preview. Do not require a surviving failed Oban job record to authorize recovery. Recheck the managed association, latest publication, and applicable live work on the server when reset is requested; if an update has started or the preview has become ready, do not recreate the section based on stale failure information.

- **Acceptance:** An authorized project author or admin can reset a stale/incomplete preview after its update was cancelled, exhausted retries, or had its terminal job record pruned. The replacement uses the latest published publication and follows the existing atomic replacement and retirement behavior.
- **Acceptance:** A ready preview or one with an applicable queued/scheduled/executing/retryable update is not reset through this failure path. Concurrent Publish, update, and reset operations retain their existing ordering safeguards; failed reset leaves the previous association recoverable.
