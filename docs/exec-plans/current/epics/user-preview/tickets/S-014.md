# S-014: Launch Full Course Preview from Publish with a complete preview shell

- **Status:** Approved and pending creation
- **Qualification:** Qualified. Code and test inspection establish the missing Publish entry and project preview shell; Q10 defines the section-publication boundary. This Story is the first user-visible entry and precedes S-013.
- **Lane:** D, fourth; scheduled after S-016, which is not a technical prerequisite. Technical prerequisites are S-012, S-015, and S-002; S-013 follows this Story.
- **Ticket:** pending.

## Description

Add Preview published course beside the latest published version and open Learn in a new tab using the author-linked preview user.

- **Requirements:** [MER-6158](https://eliterate.atlassian.net/browse/MER-6158), R-007, R-008. Full requirements are in the epic ticket.
- **Scope:**
  - Confirm the preview section is current before launch. Show updating/failed states, with Reset Preview available after failure.
  - Show a Full Course Preview banner throughout course navigation. The primary Exit preview action closes the tab, assuming success; the original authoring tab stays open.
  - Use student presentation without an instructor selector.
  - Preserve normal authentication, saved preview progress, the Publish table, and other preview flows.
- **Technical approach:** Extend the existing Publish UI and preview banner/session plumbing, consuming S-012’s readiness/recovery responses, S-015’s identity handoff, and S-002’s student presentation. Do not introduce origin-specific return tracking or a close-failure fallback. Proposed implementation details are provisional; required behavior and binding constraints remain mandatory.
- **Acceptance criteria:**
  - **Positive:**
    - **AC1** A published project exposes Preview published course beside the latest version. It opens Learn only after S-012 confirms the section is current/complete; pending or failed updates show the corresponding response without launch-time refresh. Failed state offers the common Reset Preview action and explains that the shared preview restarts with fresh progress.
    - **AC2** Full Course Preview displays an accessible banner and primary exit throughout supported course navigation; Exit preview closes the preview tab and leaves the original authoring tab open.
    - **AC3** Keyboard operation, visible focus, narrow screens, and increased zoom work for the launch/banner/exit. Launch opens a new tab and that behavior is announced.
    - **AC4** Project preview launches use the current identity selected by S-015 and preserve normal-use progress plus actual-author authorization, including older revisions retained by existing in-progress graded attempts under Q10 during normal use. Explicit failed-state Reset Preview replaces the section and starts with fresh progress.
  - **Negative:**
    - **AC5** Unpublished projects have no working launch action, and unauthorized direct requests are denied by S-012.
    - **AC6** Draft content and instructor perspective controls are absent; Full Course Preview does not require S-003.
    - **AC7** Publish table, other publication actions, ordinary student delivery, author Page Preview, and existing product-template exit behavior remain intact.
    - **AC8** Project Full Course Preview has no origin-specific return URL, authoring redirect, or close-failure fallback. Exit preview closes the tab without deleting preview records or logging out actual author/learner accounts.
- **Prerequisites:** S-012, S-015, S-002.
- **Size:** M.
- **Feature flags:** None. This Story exposes the first project preview entry together with its completed banner and exit.
