## Description

Make the delivery page layout, header, content, and references render from caller-supplied display data, so author Page Preview can use them without a learner account.

## Technical Guidance

Start with `student_delivery_lesson.html.heex`, `page.html.heex`, `lib/oli_web/components/delivery/layouts.ex`, `Student.Utils.page_header/1`/`references/1`, and `LessonLive`'s content layout. Use existing component attributes or a small input structure. Keep learner loading, enrollment, attempt creation, and account-only event handling in delivery callers; omit account-only controls when preview cannot supply them.

MER-6228 connects the basic and advanced author-preview entry points to these components. Do not build a general rendering framework or fabricate learner IDs to satisfy existing helpers. The parent Story lists the advanced-wrapper and other consumer constraints.

### Size and feasibility

- **Size:** L.
- **Single-engineer feasibility:** Feasible for an engineer comfortable with Phoenix rendering. Extract display inputs while keeping learner lifecycle and account-dependent behavior in delivery callers.

## Acceptance criteria

- The shared presentation renders with existing learner state and with authorized author-preview data but no database-backed learner.
- Rendering preview creates no user/hidden-user account, section, enrollment, persisted attempt, or progress.
- Normal delivery retains its layout, controls, and behavior. Preview-specific omissions can be supplied explicitly without maintaining copied delivery markup/styles.

- **Feature flags:** None.
- **Prerequisites:** None.
