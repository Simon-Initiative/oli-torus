## Description

## Scope

Apply first-use dedicated-user provisioning and the selected preview user throughout project preview launch, rendering, activity requests, and exit. Verify cross-project fresh progress, authorization, real-session preservation, and isolation from other preview contexts.

## Technical Guidance

### Resolve the preview user for each delivery request

Keep authenticated author/learner identity separate from the user whose preview attempts are being rendered or changed. Resolve the authorized preview user at the controller plug and equivalent LiveView mount boundary, before enrollment and page/attempt loading. Supply it consistently to the existing delivery assigns and `OliWeb.Common.SessionContext`, retaining the authenticated accounts separately for authorization. Do not replace browser-session authentication tokens or log in/out the generated user.

Carry the validated preview context through page navigation, refresh, LiveView reconnect, and activity/adaptive requests. Validate the author, current preview-user association, and project/section together; an existing enrollment or a client-supplied user ID alone is insufficient. Keep the context specific to the preview request instead of a single browser-wide active section. Reuse existing signing and delivery setup where suitable; the exact transport and helper structure remain provisional.

Audit affected activity paths for direct browser-session identity reads. For example, `lib/oli_web/controllers/api/attempt_controller.ex` reads `:current_user_id` from the session for some actions. Those preview operations must use the validated preview user rather than accidentally attributing their effects to the real learner. Scope adaptations to preview-capable operations and retain normal delivery behavior.

- **Acceptance:** A real learner tab, two project-preview tabs, and an authorized admin section-preview tab can navigate and submit supported interactions without changing one another's account or section context, including when learner and admin preview target the same section.
- **Acceptance:** Closing preview leaves authenticated author/learner sessions intact and needs no restoration request. Refresh/reconnect retains the intended preview user; reset, revoked authorization, and forged or mismatched context cannot continue with a stale user or fall back to another identity.

Use the parent [F-007](https://eliterate.atlassian.net/browse/MER-6217) for project preview behavior and the delivered [F-010](https://eliterate.atlassian.net/browse/MER-6220) user resolver/reset contract.

- **Project preview integration:** Consume [T-014](https://eliterate.atlassian.net/browse/MER-6235), [T-015](https://eliterate.atlassian.net/browse/MER-6236), [T-016](https://eliterate.atlassian.net/browse/MER-6237)’s authorized launch/readiness/session contract. Resolve or create the author’s dedicated preview user before entering project Full Course Preview, enroll it in each authorized project preview section as needed, and use it consistently for rendering, attempts, and activity requests. Preserve actual author authorization and normal learner session/identity through entry and tab-close exit. Closing the preview tab leaves the reusable preview user and project section intact and requires no tracked return URL or fallback redirect. Reopening preview after reset uses the new link; existing tabs may need to be reopened. [T-004](https://eliterate.atlassian.net/browse/MER-6225), [T-005](https://eliterate.atlassian.net/browse/MER-6226) supplies the admin section enrollment/context adapter; keep regular instructor and separate author-page/question contexts unchanged.
- **Acceptance criteria:**
  - Launch resolves or creates the current author-linked user and enrolls it in the authorized project preview section as needed.
  - Rendering, navigation, activity requests, and tab-close exit preserve the selected preview identity, actual-author permissions, and normal learner/SSO session behavior.
  - Launches across projects reuse the same current user; reopening after Reset Preview User uses the replacement identity and fresh progress. Existing tabs may need to be reopened.
  - Unauthorized project access, stale/forged identity context, and failed provisioning cannot fall back to a real learner or shared hidden user. Other authors and other preview contexts remain unaffected.
