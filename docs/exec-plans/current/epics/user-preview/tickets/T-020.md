## Description

Use the author's current dedicated preview user throughout project preview launch, enrollment, rendering, navigation, and activity requests without changing their real login.

## Technical Guidance

Consume MER-6220's resolver/reset capability and MER-6236's authorized launch/readiness context. Enroll the selected user in each authorized project preview section as needed, using MER-6220's role rule: instructor for admins and student/learner for regular authors. Keep Full Course Preview's student-only presentation regardless of enrollment role. Keep the real author responsible for project access; a generated enrollment alone is insufficient authorization.

Resolve the preview user at the controller plug and equivalent LiveView mount before enrollment/page/attempt loading. Supply it to delivery assigns and `OliWeb.Common.SessionContext`, retaining authenticated accounts separately. Carry validated author/current-user/section context through page links, refresh/reconnect, adaptive, and activity requests. Exact transport/helper design is provisional; reuse existing signing/setup rather than a browser-wide active identity.

Audit direct session identity reads in affected operations: `lib/oli_web/controllers/api/attempt_controller.ex` reads `:current_user_id` for some actions. Preview effects must use the validated preview user, not the real learner. Do not replace session authentication tokens or log the generated user in/out.

## Acceptance criteria

- Admin preview users receive instructor enrollment; regular authors receive student/learner enrollment, including after reset. Both see the student-only Full Course Preview presentation.
- Review and Publish consistently use the current author-linked user across projects, including attempts and activities. After Reset Preview User, later launches use the replacement and fresh progress; old tabs may need reopening.
- A real learner tab, two project previews, and admin section preview can interact without replacing one another's user/section, including learner/admin preview of the same section. Refresh/reconnect preserves valid context.
- Tab-close exit leaves actual author/learner authentication and reusable users/sections intact, with no restoration request, return tracking, or fallback redirect.
- Reject unauthorized projects, forged/mismatched/stale contexts, revoked permissions, and failed provisioning without falling back to real learners/shared hidden users. Reset invalidates old-user use. Preserve other authors and separate page/question/template preview behavior.
