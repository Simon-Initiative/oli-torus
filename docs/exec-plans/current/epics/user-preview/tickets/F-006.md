## ⭐ Feature: Inaccurate previews

**Figma frames / prototype:** [Figma](https://www.figma.com/design/S8qAFhjjlnRyTHCg2Dyb8p/User-Preview-Overhaul?node-id=484-13207&t=5eBSflw0qUqbFcPl-1)
**Readiness:** Pending question

### User Need

As an author, I want to know when content is unavailable or behaves differently in page preview, so that I can distinguish preview limitations from problems with my content.

### Acceptance Criteria

**Successful behavior**

- When content has a known preview limitation, display an information icon next to the affected content or its placeholder.
- The icon opens a tooltip explaining the specific limitation in plain language.
- Distinguish between content that is unavailable, content with limited functionality, and content that uses sample data.
- If content cannot be displayed, retain a labeled placeholder so authors can identify what belongs in that location.
- Use consistent messaging for the following limitations:

| **Content / activity** | **Preview messaging** |
| --- | --- |
| **LTI external tool** | “You cannot interact with this tool in page preview.” |
| **File upload** | “File uploads are not available in page preview.” |
| **Directed discussion** | “Posting to discussions is not available in page preview.” |
| **Logic Lab** | “You can open this lab in page preview, but scores are not recorded.” |
| **Activity reports** | “This is sample data. Actual activity reports are not available in page preview.” |
| **OLI embedded activities** | If a preview session cannot be created: “Preview is not available for this activity.” |
| **Surveys** | “After submitting this survey in page preview, you cannot reset it here.” |
| **Alternatives** | “Page preview shows all alternatives. Students receive content according to the configured selection rules.” |
| **Page collaborative spaces** | Display a placeholder: “Collaborative spaces are not available in page preview.” |

**Exceptions and safeguards**

- Show limitation indicators only for affected content. Ordinary scored activities that work in preview must not be labeled as unsupported.
- Preview limitations must not prevent authors from reviewing other content on the page.

### Accessibility Requirements

- **Keyboard:** Use a keyboard-focusable button for each information icon. Open its tooltip on keyboard focus and pointer hover, and allow dismissal with Escape without moving focus.
- **Semantics and labels:** Give each trigger a descriptive accessible name, such as **Preview limitation: File upload**, and associate the tooltip text using aria-describedby. Hide decorative icons from assistive technology.
- **Tooltip behavior:** Keep the tooltip visible while the trigger or tooltip is hovered, or while the trigger has focus, unless dismissed. Tooltips must not contain interactive controls; use an appropriate popover if actions are needed.
- **Content and visibility:** Keep unavailable-content placeholders in the normal reading order. Ensure messages remain readable at increased zoom and do not rely on color alone to communicate limitations.

- Normal activities evaluate in the browser through /project/test/evaluate; answers, scores, and hints are not persisted.
