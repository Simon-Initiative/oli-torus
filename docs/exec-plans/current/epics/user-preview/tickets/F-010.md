## Description

### Manage and reset the author-linked preview user

- Author account details/settings provide Reset Preview User. An authenticated author can create and link a fresh preview user to their own author account, independently of any project preview section’s update status.
- Future project Full Course Preview launches and authorized admin section previews use the author’s same currently linked preview user. Replacing the user naturally provides fresh progress in those sections; do not clear or delete attempts/progress explicitly and do not recreate shared sections for this action.
- Keep this preview association distinct from normal learner/SSO account links. Preserve actual author and learner accounts, ordinary course progress, project authorization, and separate author Page Preview/Question Preview behavior. Another author’s preview-user association must not be changed.
- Mark newly generated and superseded preview users so they remain identifiable by database query. Do not delete old preview users as part of reset; cleanup is outside scope.
- Always use a dedicated author-linked preview user for project Full Course Preview and admin section preview. Whichever supported preview entry is used first creates it if absent; reuse it across projects/authorized admin sections and replace it only on explicit Reset Preview User. Failed provisioning does not fall back to a real learner or shared section-hidden identity.

## Technical Guidance

### Delivery requirements

Give each author one dedicated preview user, reused across project previews and authorized admin section previews, with Reset Preview User in account settings.

- **Scope:**
  - Create and link the user lazily on first supported use, through an association distinct from normal learner/SSO accounts.
  - Reset creates a fresh generated user and atomically replaces the current link. New progress follows from the new user ID; keep old records and shared project sections intact.
  - Mark current and superseded author-owned preview users so database queries and remaining legacy fallback selection can distinguish them.
  - Use the selected user consistently throughout project Full Course Preview while preserving actual-author authorization and normal learner authentication. [T-004](docs/exec-plans/current/epics/user-preview/tickets/T-004.md), [T-005](docs/exec-plans/current/epics/user-preview/tickets/T-005.md) integrates admin section entries.
- **Technical approach:** Reuse existing generated-user and account-settings patterns with a distinct current preview-user association and durable purpose/ownership information. Integrate the resolver with [T-014](docs/exec-plans/current/epics/user-preview/tickets/T-014.md), [T-015](docs/exec-plans/current/epics/user-preview/tickets/T-015.md), [T-016](docs/exec-plans/current/epics/user-preview/tickets/T-016.md)’s launch/session boundary and activity paths; exact schema and component choices remain provisional. Add no cleanup or explicit progress-clearing operation. Proposed implementation details are provisional; required behavior and binding constraints remain mandatory.
- **Acceptance criteria:**
  - **Positive:**
    - **AC1:** An authenticated author can select Reset Preview User in their own account details/settings and receives accessible success or failure feedback.
    - **AC2:** Successful reset creates a fresh marked preview user and atomically links it as that author’s current preview user. Future project Full Course Preview launches use it across projects with newly established preview enrollments as needed; [T-004](docs/exec-plans/current/epics/user-preview/tickets/T-004.md), [T-005](docs/exec-plans/current/epics/user-preview/tickets/T-005.md) consumes the replacement for subsequent admin section previews.
    - **AC3:** Reset naturally starts fresh progress under the new user ID; it does not recreate shared preview sections or clear stored attempts/progress. Other authors’ current preview-user associations remain unchanged. For an admin, replacing this same user also starts fresh progress in subsequent admin section previews through [T-004](docs/exec-plans/current/epics/user-preview/tickets/T-004.md), [T-005](docs/exec-plans/current/epics/user-preview/tickets/T-005.md).
    - **AC4:** A direct database query identifies current and superseded generated preview users after repeated resets and distinguishes author-owned preview users from legacy shared identities. Real learner accounts are excluded; [T-004](docs/exec-plans/current/epics/user-preview/tickets/T-004.md), [T-005](docs/exec-plans/current/epics/user-preview/tickets/T-005.md) can exclude superseded author-owned records from shared fallback without relying on the current author link.
    - **AC5:** Project preview rendering, navigation, activity requests, and exit use the intended identity while retaining actual-author permissions and preserving the author’s ordinary learner/SSO link and authentication/session behavior.
    - **AC6:** First supported project/admin preview use creates/links one dedicated preview user when absent; subsequent launches reuse it until explicit reset. [T-004](docs/exec-plans/current/epics/user-preview/tickets/T-004.md), [T-005](docs/exec-plans/current/epics/user-preview/tickets/T-005.md) integrates admin entries with the same resolver. Concurrent provisioning/reset calls leave one current association, and failed reset preserves the prior association.
  - **Negative:**
    - **AC7:** Forged author/user IDs cannot reset another author’s association or grant access to an unauthorized project/section. Generated preview identities do not enter normal learner/SSO account-link flows. Provisioning failure cannot silently fall back to real learner or shared section-hidden identities.
    - **AC8:** Ordinary learner progress, regular instructors’ own identities, and author Page Preview/Question Preview remain unaffected. Admin previews change only through [T-004](docs/exec-plans/current/epics/user-preview/tickets/T-004.md), [T-005](docs/exec-plans/current/epics/user-preview/tickets/T-005.md)’s unified identity integration. Shared project-section Reset Preview remains a separate failed-state operation.
    - **AC9:** No cleanup job, old-user deletion, retention mechanism, or explicit progress-clearing operation is introduced. Superseded users remain marked for later cleanup.

- **Analysis:**
  - **Existing behavior:** `lib/oli_web/live/author_settings_live.ex` provides authenticated author Details and settings events. `lib/oli/accounts/schemas/author.ex` has many linked users through `users.author_id`; `lib/oli_web/views/authoring_view.ex` uses a single-result author-linked-account lookup. `Accounts.link_user_author_account/2` serves normal learner/SSO linkage. These session/runtime implications require explicit integration.
