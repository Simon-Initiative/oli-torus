# S-002: Apply route-derived student presentation to delivery

- **Status:** Created and verified
- **Qualification:** Qualified. Ordinary routes, rendering, persistence, and route-mode helpers already exist. Role-dependent UI still derives presentation from the actual instructor role. This Story applies the route-derived presentation independently of authorization; S-016 owns admin identity provisioning.
- **Lane:** A, second.
- **Ticket:** [MER-6183](https://eliterate.atlassian.net/browse/MER-6183)

## Description

Use the URL family to select Instructor View or student presentation, while keeping the actual actor’s permissions and existing persistent progress.

- **Requirements:** [MER-6158](https://eliterate.atlassian.net/browse/MER-6158), R-001, R-007, R-008. Full requirements are in the epic ticket.
- **Scope:**
  - Instructor routes render instructor presentation and navigation; ordinary delivery routes render student presentation and navigation.
  - Student Preview includes My Notes, its student default, and learner Class Notes, while hiding instructor-only controls.
  - Make the same student presentation available to project Full Course Preview without requiring the perspective selector. Admin identity provisioning belongs to S-016.
- **Technical approach:** Reuse the existing route-derived delivery presentation assign (renamed to `instructor_view` by MER-6182) and existing delivery URL helpers instead of adding a cookie, session preference, or query parameter. Apply it to verified role-sensitive UI branches while retaining actual-role checks for authorization. Proposed implementation details are provisional; required behavior and binding constraints remain mandatory.
- **Acceptance criteria:**
  - **Positive:**
    - AC1: With the authorized actor/effective user supplied by the entry flow, instructor and admin previews render the applicable perspective and navigate the existing route families. S-016 provides unified admin identity setup.
    - AC2: Student Preview uses student UI, including My Notes/default behavior and learner Class Notes, while keeping the actual actor’s authorization.
    - AC3: Student Preview uses existing persistent attempt/progress handling for its supplied user and introduces no automatic reset. Regular instructors use their own user; S-016 supplies the author-linked admin preview user.
    - AC8: The student-presentation behavior is callable without the S-003 selector, allowing S-014 to opt in its project preview context.
  - **Negative:**
    - AC5: URL/session manipulation cannot grant another section’s preview access or alter the actor’s role.
    - AC6: Privileged instructor-only controls do not appear in Student Preview; ordinary students and separate author template-preview sessions are unchanged.
    - AC7: Perspective follows the route family without a separate perspective cookie, session preference, or query parameter; this presentation Story introduces no new attempt store or identity mechanism.
- **Prerequisites:** None.
- **Size:** M.
- **Feature flags:** None. Entry UI is provided by S-003 once this behavior is available.

- **Analysis:**

Admins with a user account already pass admin enrollment checks. [ProductsController](lib/oli_web/controllers/products_controller.ex) and [TemplatePreview](lib/oli/delivery/template_preview.ex) already create/reuse a hidden instructor and establish its login for template preview.

Class Notes is also learner functionality and must remain available. [SetPreviewMode](lib/oli_web/live_session_plugs/set_preview_mode.ex) and [Student.Utils](lib/oli_web/live/delivery/student/utils.ex) already distinguish route modes; presentation must use that distinction independently of authorization. Admin identity gaps, including adaptive entry without a current user, are handled by S-016 rather than by this presentation Story.
  - **Verification and uncertainty:** Code and tests were inspected, not run. [Template preview tests](test/oli/delivery/template_preview_test.exs) and [controller tests](test/oli_web/controllers/products_controller_test.exs) cover identity reuse and user preservation; [enrollment tests](test/oli_web/live_session_plugs/require_enrollment_test.exs) cover admin access. Development must verify affected UI branches, route coverage, separation of actual-role authorization from UI presentation, and compatibility with existing author-template sessions.
- **Technical analysis:**
  - **Binding constraints:** Preserve actual user/author roles, ordinary Student Preview URLs, existing persistent attempts/progress, and existing author-template behavior. Keep original-return state separate from presentation. S-014 must be able to reuse student presentation without S-003.
  - **Route-derived presentation:** Reuse the existing section-delivery presentation flag, derived from router/live-action metadata and equivalent controller setup; S-001 renames it from `preview_mode` to `instructor_view` and updates its consumers. The presentation change can still be developed independently; coordinate the internal name with whichever change lands first. Instructor routes select instructor presentation and links; ordinary routes select student presentation and links. Apply this to annotation tabs/defaults and other verified UI branches while keeping actual-role assigns for authorization. Preserve learner Class Notes and supported interactions. No separate perspective cookie, session preference, or query parameter is needed.
  - **Reuse and compatibility:** Reuse `PageContext`, delivery renderers, and existing route helpers. Preserve explicit legacy author-template context when resolving presentation. S-014 supplies its distinct project context and consumes the same student rendering behavior. These implementation choices remain provisional within the binding constraints.
- **Prerequisite handoffs:** None. S-001 is the scheduled predecessor, not a prerequisite for ordinary delivery presentation. Provide student presentation to S-003/S-004/S-005 and S-014; S-016 integrates the admin identity and toggle without becoming a prerequisite for this presentation work.
- **Sizing analysis:** M; bounded role-dependent UI and route-helper integration, with identity provisioning owned by S-016.
