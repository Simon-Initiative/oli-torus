## Description

**Figma frames / prototype:** [Figma](https://www.figma.com/design/S8qAFhjjlnRyTHCg2Dyb8p/User-Preview-Overhaul?node-id=484-14390&t=0rxzI72xh8keuZhp-1)

### User Need

As an instructor, I want to switch between instructor view and student preview while staying on the content I’m reviewing, so that I can understand the student experience and check how my customizations appear to students.

### Acceptance Criteria

**Successful behavior**

- Opening student preview from **course content, customize content,** or the **Manage** page displays a header with a clearly labeled Student preview dropdown (anywhere instructors see a student preview).
- The dropdown allows instructors to switch between **Student preview** and **Instructor view.** Its label always reflects the active view.
- Switching views preserves the current course page so instructors can review the same content from either perspective.
- The **Return to [origin]** button reflects the location from which the instructor initially entered preview. Switching views does not change that destination.
- Selecting **Return to [origin**] takes the instructor back to that location.

**Exceptions and safeguards**

- Within an activity bank, the instructor-view header and view-switching control are hidden because there is no equivalent student view.
- A clearly labeled back control returns the instructor to the containing course page, where the instructor-view header and view-switching control reappear.

### Accessibility Requirements

- **Keyboard:** The view selector, its options, the return button, and the activity-bank back control must be keyboard operable with visible focus indicators. The dropdown must support the keyboard interactions appropriate to its implemented pattern, including Escape to close.
- **Semantics and states:** Use a semantic dropdown control with an accessible name that identifies its purpose and current view. Expose its expanded/collapsed state and the selected option to assistive technology. Use semantics and keyboard behavior consistently for the chosen dropdown pattern.
- **Focus:** Closing the dropdown with Escape returns focus to its trigger. After switching views, maintain focus on the view selector when it remains available. Returning from an activity bank restores focus to the control that opened it, or a logical location on the containing page if that control is unavailable.
- **Assistive technology:** Make the active view clear through text, rather than color alone. Announce view changes without requiring users to locate the updated header. Return and back controls must have descriptive accessible names that identify their destinations.

## Technical Guidance

### Suggested approach

For regular instructors, use the logged-in user account for both Instructor View and Student Preview, including content interaction and saved progress. Switching views does not create or substitute a preview user. The route determines which view is shown; the instructor's identity and permissions remain unchanged.

- Move instructor routes to `/instructor/...`, redirect authorized legacy links, and preserve the current resource and original safe return destination.
- Derive `instructor_view` from the route: instructor routes show Instructor View; ordinary delivery routes show Student Preview for the authorized instructor.
- Add the selector and bank-management header/back exception in this Story. Explanatory bank notes and gating behavior are delivered by their respective Stories.
- For admins, use the dedicated author-linked user supplied by [MER-6220](https://eliterate.atlassian.net/browse/MER-6220), even when the admin also has a real learner account. Enroll that user as an instructor in each authorized section. Both perspectives use the same user and enrollment.

### Existing code and integration points

`PreviewRoutes` and `PreviewReturn` in `lib/oli_web/delivery/instructor/` supply route and safe-return helpers. `Layouts.instructor_preview_header/1` provides the current header. `Student.Utils` and `SetPreviewMode` already distinguish instructor and ordinary delivery routes.

`UserAuth.auto_enroll_admin/2`, `Sections.ensure_hidden_instructor/1`, `TemplatePreview.resolve_launch_identity/2`, and `ProductsController.preview_launch/2` currently select or log in shared hidden users. MER-6225 replaces all shared-user selections, including regular-author template preview, and removes the shared-user helpers after updating scenario/test callers. Admin preview users receive instructor enrollment; regular authors receive student/learner enrollment. `PageDeliveryController.page_preview/2` also needs the admin-without-current-user adaptive path covered.

### Constraints and checks

- Generated enrollment alone must not authorize access: require the current owning admin, current preview-user association, and requested section. Check controller, LiveView, adaptive, and activity requests, including logout, revoked permission, reset, and forged context.
- Keep real learner/SSO sessions unchanged. Do not replace the browser login with the preview user; simultaneous learner and admin-preview tabs must retain their own users and progress.
- Remove shared-user selection and fallback. Pass the persistent preview user struct or ID to delivery as authorized preview context, never as an authenticated login. Remove template preview's hidden-user login/logout while preserving its return behavior. Provisioning failure must not select a real learner, another author's user, or shared fallback.
- Audit session-derived identities throughout preview entry, rendering, and activity processing. Real accounts remain the authentication/authorization actors; preview attempts, progress, grades, and user-attributed effects use the validated delivery preview user. Cover both real-learner-login and author-only sessions, including refresh/reconnect and callbacks.
- After Reset Preview User, subsequent admin entries enroll the replacement user. Do not migrate/clear progress, delete old users, grant global admin status, or mark real sections/products as disposable previews.
- Preserve regular instructor behavior, separate author page/question previews, and project preview's student-only shell.

The sub-tasks define the implementation split and focused checks. Reuse existing authorization, enrollment, and rendering code; exact helper and context shapes are engineering decisions.

## QA Misc

### Suggested QA Steps

**Setup:** Use an instructor enrolled in a section, two admins with separate author accounts, and an ordinary learner. Include basic, graded, adaptive, and bank-selection pages. Give one admin a real learner login as well.

1. As the instructor, enter preview from Course Content, Customize Content, and Manage. Switch views on the same page; confirm the selector label and route match the view, and Return still leads to the original entry location. In Student Preview, confirm privileged instructor controls are hidden and My Notes/learner Class Notes work.
2. Follow page links, refresh, and open an authorized legacy instructor link. Confirm the resource and intended view are preserved. Open bank management; confirm the header/selector disappear and the back control restores them on the containing page.
3. Answer activities in both views. Confirm the instructor uses the same logged-in user and saved progress throughout; no generated preview user is substituted.
4. As each admin, preview the same section and answer activities across basic, graded, and adaptive delivery. Confirm each admin uses their own author-linked preview user with instructor enrollment, and switching views preserves that user's progress.
5. Keep a real learner tab open alongside admin preview; refresh/reconnect and submit activities in both. Confirm their progress stays separate and neither login changes. Repeat admin preview with an author-only session and after Reset Preview User; new entries must use the replacement user.
6. Open and exit product/template preview as a regular author and an admin. Confirm author-linked users have learner and instructor enrollment respectively, return behavior still works, and the real login is preserved. With developer assistance, confirm launch and activity requests never select a shared user or create a preview-user authentication token. Check that grades, events, triggers, and callback effects are attributed to the preview user, not the real learner.
7. Try unauthorized section access, another author's preview context, and a previously valid context after logout, permission removal, or user reset. Confirm requests are denied without falling back to a real learner or shared user. Simulate provisioning failure with developer assistance and confirm the same safeguard.
8. Use the selector, Return, and bank back control by keyboard and screen reader. Check visible focus, Escape, selected/expanded states, view announcements, and focus restoration. Compare light/dark presentation with the linked designs.
