### User Need

As an instructor, I want to switch between instructor view and student preview while staying on the content I’m reviewing, so that I can understand the student experience and check how my customizations appear to students.

### Acceptance Criteria

**Successful behavior**

- Opening student preview from **course content, customize content,** or the **Manage** page displays a header with a clearly labeled Student preview dropdown (anywhere instructors see a student preview).
- The dropdown allows instructors to switch between **Student preview** and I**nstructor view.** Its label always reflects the active view.
- Switching views preserves the current course page so instructors can review the same content from either perspective.
- The **Return to [origin]** button reflects the location from which the instructor initially entered preview. Switching views does not change that destination.
- Selecting **Return to [origin**] takes the instructor back to that location.

**Exceptions and safeguards**

- Within an activity bank, the instructor-view header and view-switching control are hidden because there is no equivalent student view.
- A clearly labeled back control returns the instructor to the containing course page, where the instructor-view header and view-switching control reappear.

### Accessibility Requirements

- **Keyboard:** The view selector, its options, the return button, and the activity-bank back control must be keyboard operable with visible focus indicators. The dropdown must support the keyboard interactions appropriate to its implemented pattern, including Escape to close.
- **Semantics and states:** Use a semantic dropdown control with an accessible name that identifies its purpose and current view. Expose its expanded/collapsed state and the selected option to assistive technology. Use semantics and keyboard behavior consistently for the chosen dropdown pattern.
- **Focus:** Closing the dropdown with Escape returns focus to its trigger. After switching views, maintain focus on the view selector when it remains available. Returning from an activity bank restores focus to the control that opened it, or a logical location on the containing page if that control is unavailable.
- **Assistive technology:** Make the active view clear through text, rather than color alone. Announce view changes without requiring users to locate the updated header. Return and back controls must have descriptive accessible names that identify their destinations.
