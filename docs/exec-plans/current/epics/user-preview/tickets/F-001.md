## Description

**Figma frames / prototype:** [Figma](https://www.figma.com/design/S8qAFhjjlnRyTHCg2Dyb8p/User-Preview-Overhaul?node-id=484-14390&t=0rxzI72xh8keuZhp-1)

### User Need

As an instructor, I want to switch between instructor view and student preview while staying on the content I’m reviewing, so that I can understand the student experience and check how my customizations appear to students.

### Acceptance Criteria

**Successful behavior**

- Opening student preview from **course content, customize content,** or the **Manage** page displays a header with a clearly labeled Student preview dropdown (anywhere instructors see a student preview).
- The dropdown allows instructors to switch between **Student preview** and **Instructor view.** Its label always reflects the active view.
- Switching views preserves the current course page so instructors can review the same content from either perspective.
- The **Return to [origin]** button reflects the location from which the instructor initially entered preview. Switching views does not change that destination.
- Selecting **Return to [origin**] takes the instructor back to that location.

**Exceptions and safeguards**

- Within an activity bank, the instructor-view header and view-switching control are hidden because there is no equivalent student view.
- A clearly labeled back control returns the instructor to the containing course page, where the instructor-view header and view-switching control reappear.

### Accessibility Requirements

- **Keyboard:** The view selector, its options, the return button, and the activity-bank back control must be keyboard operable with visible focus indicators. The dropdown must support the keyboard interactions appropriate to its implemented pattern, including Escape to close.
- **Semantics and states:** Use a semantic dropdown control with an accessible name that identifies its purpose and current view. Expose its expanded/collapsed state and the selected option to assistive technology. Use semantics and keyboard behavior consistently for the chosen dropdown pattern.
- **Focus:** Closing the dropdown with Escape returns focus to its trigger. After switching views, maintain focus on the view selector when it remains available. Returning from an activity bank restores focus to the control that opened it, or a logical location on the containing page if that control is unavailable.
- **Assistive technology:** Make the active view clear through text, rather than color alone. Announce view changes without requiring users to locate the updated header. Return and back controls must have descriptive accessible names that identify their destinations.

## Technical Guidance

### Admin preview identity and integration

Reuse each admin’s author-linked preview user for section previews instead of the affected per-section shared-admin fallback.

- **Scope:**
  - After actual-admin authorization, ensure the preview user has instructor enrollment in the requested section. Instructor View and Student Preview keep the same identity and enrollment; the URL selects presentation.
  - Integrate controller, LiveView, adaptive, activity, and affected admin template entry paths without a second shared-user substitution.
  - Require the current owning admin and association: generated enrollment alone cannot authorize after logout, role loss, or reset.
  - Exclude current and superseded author-owned preview users from remaining legacy shared fallback queries. Preserve ordinary instructors, normal sessions, and project Full Course Preview’s student-only shell.
- **Technical approach:** Consume [F-010](https://eliterate.atlassian.net/browse/MER-6220)’s resolver and durable classification, reuse existing enrollment operations, and wire the selected identity through the existing preview context. Reuse [T-002](https://eliterate.atlassian.net/browse/MER-6223)’s route presentation and [T-003](https://eliterate.atlassian.net/browse/MER-6224)’s selector. Preserve genuinely required legacy helpers; add no global admin role, migration, or cleanup. Proposed implementation details are provisional; required behavior and binding constraints remain mandatory.
- **Acceptance criteria:**
  - **Positive:**
    - **AC1:** Authorized admins with or without an ordinary learner account enter section Instructor View and Student Preview through the same author-linked preview user from [F-010](https://eliterate.atlassian.net/browse/MER-6220), including adaptive entry.
    - **AC2:** Instructor enrollment is established idempotently in each requested section after actual-admin authorization. Perspective changes preserve the user, enrollment, resource, and original section return destination.
    - **AC3:** Rendering, navigation, activity requests, and affected admin template launch use the intended preview identity without a second shared-fallback substitution.
    - **AC4:** Reset Preview User naturally supplies fresh progress through the new user ID on subsequent project/admin section previews, with instructor enrollment established as needed. Other authors’ preview identities remain unchanged.
    - **AC5:** Actual author authentication, real learner/SSO links and sessions, regular instructors’ real accounts, and non-admin legacy template behavior are preserved.
  - **Negative:**
    - **AC6:** A generated preview-user instructor enrollment alone cannot grant access without its current owning admin author. Logout, loss of admin permission, stale user associations, and forged cross-author/section context cannot bypass authorization.
    - **AC7:** Shared legacy fallback never selects current or superseded author-owned preview users. Unsupported/failed identity provisioning does not silently choose another admin’s user or a shared section user.
    - **AC8:** Regular authors gain no arbitrary real-section access; project Full Course Preview remains student-only without a selector. Author Page Preview/Question Preview retain their existing behavior.
    - **AC9:** No old-user deletion, cleanup, progress migration/clearing, global user-admin role, new admin identity store, or preview-purpose marking of real course/product sections is introduced.
- **Feature flags:** None. This integrates existing section perspectives after the shared identity and selector deliveries are available.

#### Implementation guidance

- **Scope analysis:** Integrate [F-010](https://eliterate.atlassian.net/browse/MER-6220)’s resolver into admin section-preview and affected admin product/template-preview entry paths. Ensure section-specific instructor enrollment and consistent identity through controller, LiveView, adaptive, and activity requests. Preserve regular instructors’ real identities, non-admin legacy template behavior, project Full Course Preview’s student-only shell, and existing section-return/navigation contracts. Do not create another admin identity store, migrate progress, delete old users, or mark real course/product sections as disposable preview sections.
- **Sources and design:** [Instructor Interface](https://www.figma.com/design/S8qAFhjjlnRyTHCg2Dyb8p/User-Preview-Overhaul?node-id=484-14126) and [Student Preview](https://www.figma.com/design/S8qAFhjjlnRyTHCg2Dyb8p/User-Preview-Overhaul?node-id=484-14996) establish the existing perspectives. [T-003](https://eliterate.atlassian.net/browse/MER-6224) owns the selector UI.
- **Analysis:**
  - **Existing behavior:** `UserAuth.auto_enroll_admin/2` in `lib/oli_web/user_auth.ex` obtains a section-shared hidden instructor when the admin has no current user and writes its token/context. `Sections.ensure_hidden_instructor/1` in `lib/oli/delivery/sections.ex` selects hidden users with instructor enrollment. `AuthorizeSectionPreview.call/2` in `lib/oli_web/plugs/authorize_section_preview.ex` accepts an instructor enrollment or admin author. `PageDeliveryController.page_preview/2` has an unsupported adaptive branch for an admin without a current user.
  - **Template integration:** `TemplatePreview.resolve_launch_identity/2` maps any hidden current user to shared-section fallback. `ProductsController.preview_launch/2` fetches that fallback again. Changing only one resolver would not retain the intended admin identity. Shared-user helpers also have remix, legacy-superactivity, and non-admin callers, so globally deleting them would expand scope.
  - **Remaining gap:** Admin paths do not resolve the per-author preview user or ensure its instructor role. A generated instructor enrollment could grant unintended independent access if normal instructor authorization accepts it without the owning authenticated admin. The shared hidden-user query could also select an author-owned preview user; a current-association-only exclusion fails after that user is superseded by reset.
  - **Verification:** Development must confirm the complete admin entry inventory, section/context scoping and session preservation, role-revocation behavior at relevant boundaries, and exclusion of current/superseded author-owned users from remaining shared fallback callers.
- **Technical analysis:**
  - **Binding constraints:** Use [F-010](https://eliterate.atlassian.net/browse/MER-6220)’s current author-linked preview user for admin preview regardless of whether the admin also has a real learner account. Check actual admin authorization before provisioning or enrollment. Instructor is a section enrollment role, not a global admin grant. Both perspectives keep the same preview user and roles.
  - **Identity and enrollment:** Reuse [F-010](https://eliterate.atlassian.net/browse/MER-6220)’s lazy owned-user resolver and existing enrollment operations. Ensure the generated user has the required instructor enrollment in the requested authorized section, without altering the admin’s real learner/instructor accounts. Carry the selected identity through the existing preview context and activity paths while preserving actual-author authentication and normal learner sessions.
  - **Authorization:** Treat generated admin preview users distinctly from ordinary instructors. Require the authenticated owning admin author and current preview-user association at the relevant controller/LiveView/activity boundaries; generated enrollment alone is insufficient after author logout, role loss, or reset. Preserve ordinary instructors’ authorization behavior.
  - **Fallback compatibility:** Replace affected admin auto-enrollment and template-launch shared-fallback selections, including the second fetch in ProductsController. Prevent remaining legacy fallback queries from selecting any author-owned preview user, including superseded rows, using [F-010](https://eliterate.atlassian.net/browse/MER-6220)’s durable purpose/ownership information. Keep genuinely required non-admin/legacy helpers and their behavior.
  - **Presentation and reset:** Consume [T-002](https://eliterate.atlassian.net/browse/MER-6223)’s route-derived presentation and [T-003](https://eliterate.atlassian.net/browse/MER-6224)’s selector. Student Preview uses ordinary URLs; Instructor View uses instructor URLs. Preserve existing section-origin return behavior; the project new-tab policy is separate. After Reset Preview User, subsequent admin entries resolve and enroll the replacement. No attempt/progress clearing, data migration, or cleanup is required.
- **Integration requirements:** [F-010](https://eliterate.atlassian.net/browse/MER-6220)’s reusable author-linked resolver, reset, and markers; admin request/session integration is owned by [T-005](https://eliterate.atlassian.net/browse/MER-6226); [T-002](https://eliterate.atlassian.net/browse/MER-6223)’s route-derived presentation and [T-003](https://eliterate.atlassian.net/browse/MER-6224)’s usable selector for end-to-end acceptance. [T-001](https://eliterate.atlassian.net/browse/MER-6222) is transitive.
- **Sizing analysis:** L; reuse the existing resolver, enrollment, presentation, and selector, with coordinated admin entry/API coverage and fallback safety.
