## Description

Add a secondary, question-specific Preview action and a standalone Question Preview shell using MER-6229's renderer. Preserve the bank list and restore focus on exit.

## Technical Guidance

### Size and feasibility

- **Size:** M (3–5 focused engineering days).
- **Single-engineer feasibility:** Good individual assignment. Covers the React launch control, standalone shell, retained bank state, and reliable focus return.
- **Estimate basis:** An engineer familiar with Torus; includes implementation and verification, excludes dependency/review waiting time. This is a planning estimate, not a delivery commitment.

Add the action in `ActivityBank.tsx`/the bank toolbar. Keep the originating React bank mounted while opening a separate preview window/tab, following existing author-preview launch behavior. Retain a stable opener target; if it is gone, return to a safe bank destination. This preserves list state without a new persistence store.

Use a sticky Question Preview banner and exit; reuse a small shared banner where appropriate without making the page-preview redesign a prerequisite. MER-6231 aligns the other bank actions.

## Acceptance criteria

- Every question has a secondary Preview action with a question-specific accessible name. It opens only the selected question and identifies the preview context on entry.
- Exit preserves search, filters, paging/list position, and restores the originating Preview control's focus, with a safe fallback when unavailable.
- Banner/exit remain usable while scrolling, at narrow widths, and with zoom. Supported interactions work inside the shell.
- Include no other bank questions, course navigation, instructor preview cards, or answer-key controls. Opening/exiting changes no question data and creates no section/learner attempt.
