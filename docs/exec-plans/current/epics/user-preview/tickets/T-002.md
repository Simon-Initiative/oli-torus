## Description

Use the current route to choose delivery presentation and navigation. Rename the internal delivery assign `preview_mode` to `instructor_view`; keep authorization based on the actual account's permissions.

## Technical Guidance

### Size and feasibility

- **Size:** L (6–10 focused engineering days).
- **Single-engineer feasibility:** Feasible with broad regression testing. This is more than an assign rename: presentation must separate from permissions, including notes and navigation across delivery modes.
- **Estimate basis:** An engineer familiar with Torus; includes implementation and verification, excludes dependency/review waiting time. This is a planning estimate, not a delivery commitment.

`SetPreviewMode`, `Student.Utils`, `PreviewPageContext`, controller assigns, layouts, and components already carry the presentation flag. Update those producers/consumers and internal navigation options consistently. Instructor routes use `instructor_view: true`; ordinary delivery/Student Preview uses false. No perspective cookie, session preference, or query parameter is needed.

`LessonLive` derives `is_instructor` from the real role, and `lesson/annotations.ex` uses it to hide My Notes and select Class Notes. Change presentation-sensitive branches so Student Preview shows My Notes with the student default and retains learner Class Notes. Keep role checks used for authorization.

Preserve distinct `template_preview_mode`, author/activity preview flags, and client `previewMode` payloads; translate at shared components only where necessary. Reuse `PageContext` and existing persistent attempts. Author-linked preview-user integration is MER-6225's work. Full Course Preview must be able to use student presentation without the selector.

## Acceptance criteria

- Instructor/admin previews show the correct UI and links for their route. Privileged instructor controls are absent in Student Preview; My Notes and learner Class Notes work.
- All delivery producers/consumers and regression tests use `instructor_view`. Separate author/template/activity preview behavior and payloads remain compatible.
- Regular instructors use their own user/progress; admin preview uses the user supplied by its entry flow. Add no identity store, automatic reset, or temporary attempt storage.
- Forged route/session values cannot change permissions or grant another section's preview access. Verify both controller and LiveView rendering and the existing template/enrollment tests.
