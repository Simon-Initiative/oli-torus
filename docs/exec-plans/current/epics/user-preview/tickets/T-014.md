## Description

Create or reuse one marked preview section per project and update its published content and hierarchy after each successful Publish.

## Technical Guidance

Reuse compatible section creation and update code, including external-tool setup and cache invalidation. `Blueprint.create_blueprint/5` creates resources from a publication, but `Sections.Updates.do_update/4` treats blueprint major changes as minor; choose a section/update approach that also applies hierarchy additions and removals.

Queue updates transactionally from `Publishing.publish_project/3`, independently of optional ordinary-section pushes. Reuse the Oban update worker/retries. Coordinate first creation, Publish, updates, and reset so only one association is current, no publication is missed, and obsolete jobs cannot move the section backward or modify a replacement.

Persist explicit preview identification on dedicated sections, including replacements, and retain it when retired. Current association alone is not enough for later queries. MER-6236 owns readiness/launch; MER-6237 owns failed-state replacement.

### Size and feasibility

- **Size:** XL.
- **Single-engineer feasibility:** Feasible for an experienced backend engineer in stages. Structural updates, transactional job scheduling, concurrent publication, obsolete jobs, and retained attempts create substantial correctness risk. Resolve structural-update and concurrency behavior early.

## Acceptance criteria

- First authorized creation uses the latest publication; repeated/concurrent creation reuses one section. Never-published projects are not allocated one.
- Successful Publish schedules the required update even when ordinary-section auto-push is off; rolled-back Publish leaves no job. Optional pushes cannot create competing outdated updates.
- Apply complete content/hierarchy changes and caches coherently. Failure exposes no partial completed state. Preserve attempts/progress, including older revisions retained by active graded attempts.
- Readiness remains correct after completed or failed job history is pruned. Only applicable live work counts as Updating; obsolete/retired-section jobs cannot keep it waiting indefinitely. Coordinate reads with transaction boundaries.
- Direct queries identify current and retired preview sections while excluding ordinary sections/products. Add no per-author sections, cleanup, automatic progress reset, or periodic content synchronization.
