# S-004: Inspect restricted content without changing student access

- **Status:** Created and verified
- **Qualification:** Qualified. Existing gating can block delivery or bypass it for admins, but it does not provide the approved reversible restricted/content presentation and instructor settings banner.
- **Lane:** A, fourth.
- **Ticket:** [MER-6185](https://eliterate.atlassian.net/browse/MER-6185)

## Description

Let an authorized instructor or admin reveal a gated page in Student Preview and restore its restricted view without changing student access.

- **Requirements:** [MER-6158](https://eliterate.atlassian.net/browse/MER-6158), R-003, R-008. Full requirements are in the epic ticket.
- **Scope:**
  - Show the restriction message, Instructor preview note, and Preview page / Show restricted view control, including for admins whose normal access bypasses gates.
  - Show the existing Assessment settings and Advanced gating tool links in Instructor View.
  - Keep focus and announcements correct; the reveal action changes no gate settings, exceptions, student access, or prerequisite completion. Normal preview interactions retain existing persistence.
- **Technical approach:** Reuse the gate evaluator and restriction details, keeping the restriction result separate from local revealed/hidden presentation. Apply the authorized preview behavior across relevant LiveView and controller paths; do not introduce temporary attempt storage. Proposed implementation details are provisional; required behavior and binding constraints remain mandatory.
- **Acceptance criteria:**
  - **Positive:**
    - AC1: A restricted preview shows the student message, Instructor preview note and Preview page action for the authorized actor, including admin.
    - AC2: Preview page reveals content and changes to Show restricted view; the latter restores the same restriction.
    - AC3: Toggle focus is retained, state changes are announced, and hidden content cannot hold focus.
    - AC4: Instructor View displays informational links to Assessment settings and Advanced gating tool.
  - **Negative:**
    - AC5: Ordinary students cannot see or invoke the local bypass.
    - AC6: Using the bypass changes no gating settings, student access, exceptions or prerequisite-completion state.
    - AC7: Normal persistent preview visits and interactions follow Q9; this Story adds neither automatic reset nor temporary progress storage.
- **Prerequisites:** S-002, S-003.
- **Size:** L.
- **Feature flags:** None.

## Local analysis

- **Requirements analysis:** [R-003](docs/exec-plans/current/epics/user-preview/epic.md#r-003-inspect-restricted-content-without-changing-access): restriction message plus Instructor preview note, Preview page / Show restricted view toggle, focus and announcement, Instructor View links to Assessment settings and Advanced gating tool, and no changes to student access/gating/prerequisite completion. [R-008](docs/exec-plans/current/epics/user-preview/epic.md#r-008-keep-preview-controls-accessible-and-authorized): keyboard, focus, authorized bypass. Q9 retains normal Student Preview attempt/progress persistence.
- **Scope analysis:** Add the local presentation bypass and explanatory banner across applicable basic/graded/adaptive entry paths. Evaluate restriction information for previewing admins instead of silently losing it through existing admin bypass. Do not change gating configuration or mark prerequisites complete; normal delivery interactions retain Q9 behavior.
- **Sources and design:** [Design Handoff](https://docs.google.com/document/d/1XrwiN86AETdRxxyoGanQE2pAvl484RHPM6w0prWKk6c/edit); [restricted](https://www.figma.com/design/S8qAFhjjlnRyTHCg2Dyb8p/User-Preview-Overhaul?node-id=484-15826); [bypassed](https://www.figma.com/design/S8qAFhjjlnRyTHCg2Dyb8p/User-Preview-Overhaul?node-id=529-11932); [instructor](https://www.figma.com/design/S8qAFhjjlnRyTHCg2Dyb8p/User-Preview-Overhaul?node-id=484-15942).
- **Analysis:**
  - **Existing behavior:** `Oli.Delivery.Gating.blocked_by/3` and `details/2` already evaluate and explain restrictions. `lib/oli_web/live_session_plugs/init_page.ex`, `lib/oli/delivery/page/prologue_state.ex`, and `lib/oli_web/plugs/maybe_gated_resource.ex` each bypass gates for admins. `InitPage` creates persistent page context before computing its blocking-gate display. Basic `PreviewPageContext` renders instructor content without learner setup.
  - **Remaining gap:** No approved Preview page / Show restricted view toggle or settings banner is present in the instructor page component. Existing admin bypass skips the restriction details that Student Preview must show. A change only in the basic LiveView would omit graded/adaptive/controller entry paths.
  - **Verification and uncertainty:** Static inspection only; no runtime checks. R-003 protects gates, student access, and prerequisite completion from bypass mutations. Q9 retains normal persistent preview visits and subsequent interactions; the toggle does not introduce a separate no-progress/no-grade policy. Child design must define the smallest way to retain restriction details while allowing authorized local presentation.
- **Technical analysis:** Reuse the gate evaluator and detail formatter. Within S-002’s authorized preview context, compute the student restriction presentation even for admins and retain that result separately from the local revealed/hidden state. Add the two-state control with focus and announcement behavior, and render Instructor View’s links to the existing settings destinations. Apply the selected presentation at the appropriate live/controller boundary so a bypass never changes a gate record, student exception, or completion record. Avoid creating a temporary attempt subsystem; gate-free Student Preview still uses normal delivery persistence.
- **Prerequisite handoffs:** S-002’s authorized presentation context and S-003’s usable perspective entry. S-001 supplies the Instructor View links. Exit handoff: both restricted and revealed states are usable with existing delivery content.
- **Sizing analysis:** L; multiple gating boundaries and admin bypass semantics make this broader than a single banner/toggle change.
