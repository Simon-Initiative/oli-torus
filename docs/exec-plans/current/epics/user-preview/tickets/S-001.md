# S-001: Move Instructor View to its dedicated routes

- **Status:** Created and verified
- **Qualification:** Qualified. Existing instructor routes use `/preview/...`; Q8 requires `/instructor/...` and authorized redirects for old links. Route migration is a concrete change, while existing rendering and safe-return behavior are reused.
- **Lane:** A, first.
- **Ticket:** [MER-6182](https://eliterate.atlassian.net/browse/MER-6182)

## Description

Move Instructor View from the existing `/preview/...` routes to `/instructor/...`, while preserving the current page and original safe return destination.

- **Requirements:** [MER-6158](https://eliterate.atlassian.net/browse/MER-6158), R-001, R-008. Full requirements are in the epic ticket.
- **Scope:**
  - Update instructor entry points, generated navigation, and controller redirects across lesson, Learn, container, and adaptive pages.
  - Redirect authorized legacy links to their matching new routes. Keep ordinary student delivery and author previews working.
  - Preserve basic Instructor View’s existing rendering without learner visits, attempts, scores, or progress events.
- **Technical approach:** Update the existing router, PreviewRoutes, and delivery URL helpers together. Reuse the current renderers, authorization checks, and safe-return helpers; this route migration adds no identity or attempt-storage mechanism. Proposed implementation details are provisional; required behavior and binding constraints remain mandatory.
- **Acceptance criteria:**
  - **Positive:**
    - AC1: Every supported instructor entry and generated link uses `/instructor/...` and retains its resource and original safe return.
    - AC2: Legacy URLs redirect to the matching new route for authorized instructors/admins.
    - AC3: Existing basic-page rendering, adaptive delegation, and safe fallback remain functional.
  - **Negative:**
    - AC4: A student or instructor from another section cannot gain Instructor View via either route family.
    - AC5: Ordinary student and author-preview routes retain their behavior.
    - AC6: The basic instructor page context introduces no learner visits, attempts, scoring, or progress events.
- **Prerequisites:** None.
- **Size:** L.
- **Feature flags:** None.

## Local analysis

- **Requirements analysis:** [R-001](docs/exec-plans/current/epics/user-preview/epic.md#r-001-switch-instructor-perspectives-without-losing-context): Q8 route names, current resource, original return destination, and requested-section authorization. [R-008](docs/exec-plans/current/epics/user-preview/epic.md#r-008-keep-preview-controls-accessible-and-authorized): safe returns and separation from ordinary student access. Preserve the existing no-learner-side-effect contract of basic-page Instructor View.
- **Scope analysis:** Migrate the instructor lesson, Learn, container, adaptive-page and selection-manager route family and its generated links. Include related preview navigation such as schedule/assignments where retaining old links would move the user out of the new route family. The perspective selector is S-003, student presentation is S-002, and admin identity integration is S-016. S-002 owns the delivery presentation assign rename and its consumers; this Story owns the route-prefix migration and authorized redirects.
- **Sources and design:** [Design Handoff](https://docs.google.com/document/d/1XrwiN86AETdRxxyoGanQE2pAvl484RHPM6w0prWKk6c/edit); [Instructor Interface](https://www.figma.com/design/S8qAFhjjlnRyTHCg2Dyb8p/User-Preview-Overhaul?node-id=484-14126); [existing instructor shell PRD](docs/exec-plans/current/epics/instructor_customizations/instructor_view_shell/prd.md); Q8 in the epic.
- **Analysis:**
  - **Existing behavior:** `lib/oli_web/router.ex` has both a `/preview` student-shell live session and a separate `/sections/:section_slug/preview` controller/basic-lesson scope. `lib/oli_web/delivery/instructor/preview_routes.ex` and the preview-aware helpers in `lib/oli_web/live/delivery/student/utils.ex` construct those URLs. `lib/oli_web/plugs/authorize_section_preview.ex` allows the section instructor/admin and redirects enrolled students to delivery. `lib/oli_web/delivery/instructor/preview_return.ex` already sanitizes and carries safe section/product return paths.
  - **Remaining gap:** No `/instructor/...` equivalent or legacy-to-new redirect contract exists in these route definitions. Hard-coded selection links also exist in `lib/oli/rendering/content/activity_bank_selection_preview.ex`. Updating only the main route helper would leave inconsistent navigation and potentially different authorization between Learn and lesson entry.
  - **Verification and uncertainty:** Static code inspection and test review only. `test/oli_web/live/delivery/instructor/preview_lesson_live_test.exs` covers preview navigation, safe return fallback, product-remix returns, and adaptive delegation. `test/oli_web/delivery/section_preview_route_guard_test.exs` checks shared navigation uses preview-aware helpers. These tests were read, not executed. The exact route inventory must be completed during implementation; the current admin-without-user adaptive limitation belongs to S-016.
- **Technical analysis:** Update the router, `PreviewRoutes`, and shared `Student.Utils` preview branches as one migration. Keep current renderers and live actions, and redirect authorized legacy requests to the corresponding new route while retaining revision/selection identifiers and safe query context. Apply the same actual-actor access check at both the new and legacy route boundaries, including Learn navigation. Update server-generated internal links and controller redirects; preserve `PreviewReturn` sanitization and ordinary delivery URLs. For basic pages retain `PreviewPageContext.build/4`, which avoids learner visits/attempts; do not apply a new temporary-storage policy to adaptive delivery.
- **Prerequisite handoffs:** None. Exit handoff: the new route helpers and authorized redirect contract are deployed and usable by S-003. S-016 supplies admin identity support where existing rendering needs a user record.
- **Sizing analysis:** L; two route scopes, shared navigation helpers, legacy links, and authorization must change consistently.
