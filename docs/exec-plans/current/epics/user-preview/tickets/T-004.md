## Description

Replace shared preview users with each author's dedicated preview user throughout admin section preview and author/admin product-template preview: entry, enrollment, rendering, navigation, and activity submissions. Delivery receives the persistent preview user struct or ID in an authorized preview context. The preview user is never logged in; real author and learner authentication remains unchanged.

## Technical Guidance

Consume MER-6220's resolver, enrollment-role rule, and durable ownership markers. Use the same author-linked user across authorized sections, including when the author also has a real learner account. Enroll admins as instructors and regular authors as students/learners, including after promotion or Reset Preview User. Authorize the real author/admin and requested section or template before enrollment, page loading, or attempt access.

Replace shared-user selection in `UserAuth.auto_enroll_admin/2`, `TemplatePreview.resolve_launch_identity/2`, and `ProductsController.preview_launch/2`. Cover `PageDeliveryController.page_preview/2`'s admin-without-current-user adaptive entry, controller and LiveView rendering, and activity requests. Regular-author template preview also uses the author-linked user; no preview path selects a shared singleton or substitutes a real learner account.

Pass the validated preview user struct or ID and section to delivery through navigation, refresh/reconnect, and activity requests. Keep the authenticated actor separate. Do not generate preview-user authentication tokens, call login/logout for that user, or replace the browser's real login. Remove template launch's hidden-user login and exit's hidden-user logout; exit ends only the preview context and retains the template's return behavior. Admin routes select Instructor View or Student Preview without changing identity or enrollment. Exact request-context helpers are engineering choices.

Audit session reads and writes throughout every affected preview path, including controller/API actions, LiveView mount/reconnect, adaptive and legacy activities, and downstream progress, grading, event, and trigger code. Trace values copied from the session into assigns or `SessionContext`, not just direct `get_session` calls. In particular, `lib/oli_web/controllers/api/attempt_controller.ex` reads session `:current_user_id` for activity side effects. Classify each use: authentication/authorization retains the real actor; delivery ownership and preview activity effects use the validated preview user; unrelated settings such as timezone can remain unchanged. Review activity-session identifiers and ownership checks so they cannot associate preview activity with a real learner. Record the affected paths and how each is handled in implementation/PR notes. Do not replace session identity globally or accept an unvalidated preview user ID.

Remove `Sections.fetch_hidden_instructor/1`, `Sections.ensure_hidden_instructor/1`, their shared-user creation/token helpers, and obsolete fallback branches after replacing every caller. Update `Oli.Scenarios.SectionOps` and affected tests to supply explicit scenario/test instructors for operations that need an actor. Existing shared accounts and progress remain untouched; deletion, cleanup, and progress migration are outside scope. Keep the general `hidden` flag and unrelated behavior that still needs it.

## Acceptance criteria

- An admin can enter a section that already has a shared hidden instructor, open a page, switch views, navigate, and submit an activity using only their current author-linked preview user. Cover controller, LiveView, adaptive, and product/template entry paths, with and without a real learner account. Switching preserves the resource and original safe return destination.
- A regular author can preview an authorized template and submit activities using their own preview user with student/learner enrollment, whether or not a real learner account is logged in. Admin preview users receive instructor enrollment. Neither flow changes the real account's progress.
- Two authors/admins previewing the same section use different users with independent progress. Each reuses their user across authorized sections, while attempts/progress remain section-scoped. Repeated/concurrent entry creates no duplicate users or enrollments.
- A real learner tab and a preview of the same section retain independent identity/progress. Two preview tabs retain their own section context through navigation, refresh, and reconnect. Entry and exit never authenticate the preview user or change real author/learner login; template exit preserves its return behavior.
- After Reset Preview User, subsequent entries use the replacement with the appropriate enrollment role and fresh progress. Reject stale associations; do not migrate or clear old progress.
- Reject forged or mismatched contexts, logged-out authors, and revoked section/template access before preview data or attempts can be accessed. Generated enrollment alone grants no access. Provisioning failures do not fall back to a shared user, real learner, or another author's user.
- Regression checks cover session-derived identity in the audited paths with both a real learner logged in and no real learner login. Attempts, progress, grading, and user-attributed activity effects belong to the preview user and correct section; real learner records remain unchanged. Authentication/authorization still uses the real actor. Verify refresh/reconnect and activity callbacks, and reject missing or invalid preview context rather than using the session's learner identity.
- No production, scenario, or test caller relies on the removed shared-user helpers. Update template, controller, hidden-instructor, remix, and legacy activity tests to verify the replacement behavior or use explicit fixtures. Preserve existing shared records without selecting them for new preview requests.
- Preserve ordinary instructors' logged-in identity and separate author page/question previews. Project Full Course Preview retains its student-only presentation. Add no global admin permission, second user store, or preview marker to real sections. Verify this task end-to-end without waiting for the project-preview Story.
