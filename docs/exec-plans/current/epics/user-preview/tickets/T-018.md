## Description

## Technical Guidance

### Use the shared readiness LiveView

Open Full Course Preview opens the shared project launch URL in a new tab and announces that behavior. MER-6236 owns the readiness LiveView: it displays Updating or Failed and automatically redirects to Learn in that tab once the server confirms readiness. Exit Preview remains available while waiting; Failed also offers Reset Preview. There is no Check Again button. The Review page does not implement a separate readiness interface or monitoring mechanism.

- **Acceptance:** A pending update displays the shared LiveView rather than stale content. Completion automatically redirects to Learn in the same tab without another user action. Checks do not open more tabs or enqueue update jobs. The original Review tab and its existing functionality remain intact.
- **Acceptance:** Failed state uses the shared reset explanation/action, exit, keyboard/focus behavior, and automatic readiness updates. Refresh/reconnect and missed broadcasts retain the same server-verified readiness behavior. Stale client state cannot bypass the server check.

### Delivery requirements

Replace Review’s working-content preview entry with a publication-aware Full Course Preview card.

- **Scope:**
  - Never published: explain that publication is required and offer Go to Publish.
  - Published without draft changes: show the published version and Open Full Course Preview.
  - Published with draft changes: also show the excluded-change count and Go to Publish.
  - Use the same readiness checks, failed-state Reset Preview, and new-tab shell as Publish. Preserve automated review, warnings, and the chart, with accessible status announcements and keyboard operation that do not steal focus.
- **Technical approach:** Reuse Publish’s version/diff logic and the existing Review state machinery. Connect the card to the shared project launch operation and [T-017](https://eliterate.atlassian.net/browse/MER-6238)’s completed shell, rather than creating another launch or synchronization mechanism. Proposed implementation details are provisional; required behavior and binding constraints remain mandatory.
- **Acceptance criteria:**
  - **Positive:**
    - **AC1** A never-published project explains the prerequisite and offers Go to Publish.
    - **AC2** A published project without draft changes names the published version, explains that published content is used, and offers Open Full Course Preview.
    - **AC3** Draft changes add the excluded-change count and secondary Go to Publish while preserving the primary preview action.
    - **AC4** Preview opens Learn in the section using the same latest prepared publication as Publish, in a new tab with [T-017](https://eliterate.atlassian.net/browse/MER-6238)'s banner and tab-closing exit; retained attempts follow during normal use; explicit failed-state Reset Preview recreates the section with fresh progress.
    - **AC5** Card name, readable status, keyboard operation, focus, and dynamic announcements meet the accessibility criteria in the parent Story; existing automated review, warnings, and chart remain usable.
  - **Negative:**
    - **AC6** Never-published projects cannot launch a course preview.
    - **AC7** Draft revisions are not selected by the card or launch; stale client state cannot bypass [T-014](https://eliterate.atlassian.net/browse/MER-6235), [T-015](https://eliterate.atlassian.net/browse/MER-6236), [T-016](https://eliterate.atlassian.net/browse/MER-6237)’s readiness check. Pending/failed updates are reported rather than opened, without a launch-time refresh. A failed project-preview response exposes [T-014](https://eliterate.atlassian.net/browse/MER-6235), [T-015](https://eliterate.atlassian.net/browse/MER-6236), [T-016](https://eliterate.atlassian.net/browse/MER-6237)’s Reset Preview action to authorized project authors/admins and explains its shared-state effect.
    - **AC8** Project authorization remains enforced, and a card update does not steal focus or make status dependent on color alone.
- **Size:** M.
- **Feature flags:** None. The card is exposed after its launch and shell prerequisites are complete.

Reuse publication/diff semantics from Publish and retain all existing QA controls, warning interactions, and chart behavior. Section creation, Publish-driven updates, launch readiness, and recovery are supplied by [T-014](https://eliterate.atlassian.net/browse/MER-6235), [T-015](https://eliterate.atlassian.net/browse/MER-6236), [T-016](https://eliterate.atlassian.net/browse/MER-6237); [T-020](https://eliterate.atlassian.net/browse/MER-6241) applies the current author preview user resolved by [F-010](https://eliterate.atlassian.net/browse/MER-6220) to project preview requests, and [T-017](https://eliterate.atlassian.net/browse/MER-6238) supplies the banner/exit.
- **Sources and design:** [Design Handoff](https://docs.google.com/document/d/1XrwiN86AETdRxxyoGanQE2pAvl484RHPM6w0prWKk6c/edit); [never published](https://www.figma.com/design/S8qAFhjjlnRyTHCg2Dyb8p/User-Preview-Overhaul?node-id=546-53431); [published](https://www.figma.com/design/S8qAFhjjlnRyTHCg2Dyb8p/User-Preview-Overhaul?node-id=545-51964); [draft changes](https://www.figma.com/design/S8qAFhjjlnRyTHCg2Dyb8p/User-Preview-Overhaul?node-id=546-54200).
- **Analysis:**
  - **Existing behavior:** `QaLive.render/1` in `lib/oli_web/live/qa/qa_live.ex` renders Run Review and Preview Course. The latter uses `Routes.resource_path(..., :preview, project.slug)` and opens the authoring working-content preview. `mount/3`, `read_current_review/1`, and `OliWeb.Qa.State` drive warnings and review state; they do not calculate a published-course card.
  - **Existing behavior:** `PublishView.mount/3` in `lib/oli_web/live/projects/publish_view.ex` already fetches latest and working publications and calls `Publishing.diff_publications/2`. `PublicationDetails.change_count/1` in `lib/oli_web/live/projects/publication_details.ex` counts entries in the diff's changes map; `Utils.render_version/3` supplies version formatting. These behaviors should be reused rather than invented for Review.
  - **Remaining gap:** Review has no never-published/published/draft-excluded card, version or draft count for preview, or project latest-publication launch. Its current preview link targets working content instead of the latest published course.
  - **Verification:** Child analysis must choose the minimal shared query/helper boundary and confirm how publication changes update the mounted card. Reuse existing subscriptions where applicable; do not create a new background synchronization mechanism.

  - Connect Open Full Course Preview to the same [T-014](https://eliterate.atlassian.net/browse/MER-6235), [T-015](https://eliterate.atlassian.net/browse/MER-6236), [T-016](https://eliterate.atlassian.net/browse/MER-6237) project launch used by Publish, opening in a new tab with [T-017](https://eliterate.atlassian.net/browse/MER-6238)'s completed shell. No Review return origin is stored or propagated. [T-014](https://eliterate.atlassian.net/browse/MER-6235), [T-015](https://eliterate.atlassian.net/browse/MER-6236), [T-016](https://eliterate.atlassian.net/browse/MER-6237) checks that the associated section has completed its latest Publish-driven update. Surface its updating/failed response, including the common Reset Preview action in failed state for authorized project authors/admins, instead of opening stale content; launching does not refresh the section, and the card cannot override server readiness. Preserve ’s normal revision behavior for retained attempts.
  - Keep the QA state/event/subscription behavior and chart in place. Associate the card heading, provide textual version/count information, announce dynamic card changes without stealing focus, and announce that preview opens in a new tab. Exit Preview closes the preview tab; the original Review tab stays open.
