## Description

Replace Review's working-content preview entry with the publication-aware Full Course Preview card, preserving automated review, warnings, and the chart.

## Technical Guidance

### Size and feasibility

- **Size:** M (3–5 focused engineering days).
- **Single-engineer feasibility:** Good individual assignment after the shared flow works. Covers three publication states, version/change count, accessible launch, and preservation of existing QA behavior.
- **Estimate basis:** An engineer familiar with Torus; includes implementation and verification, excludes dependency/review waiting time. This is a planning estimate, not a delivery commitment.

`lib/oli_web/live/qa/qa_live.ex` currently opens the working authoring preview. Reuse publication/version/diff logic from `PublishView`, `PublicationDetails.change_count/1`, and `Utils.render_version/3` to show the latest published version and excluded draft-change count. The card needs the count, not a duplicate Publish table model. Retain existing QA state/events/subscriptions; use a minimal shared helper where useful rather than new background synchronization.

Open the same MER-6236 readiness LiveView as Publish in a new tab. It supplies automatic ready navigation, pending/failed status, reset, and exit. MER-6238 supplies the completed banner/shell; MER-6241 applies the author-linked preview identity. Do not create another launch, polling, or reset mechanism in Review.

## Acceptance criteria

- Never published: explain the prerequisite and offer Go to Publish, with no working preview launch. Published without drafts: show the version and Open Full Course Preview. With drafts: also show the excluded-change count and secondary Go to Publish.
- Preview starts at Learn using server-confirmed current content. Waiting automatically resolves in the same new tab when ready; stale card state cannot bypass the check. Announce the new tab, leaving the original Review tab intact.
- Use the common failed-state reset explanation/action, exit, keyboard/focus behavior, and request-failure feedback. Checks create no new tabs or update jobs.
- Keep card/status information readable and independent of color; dynamic updates announce without stealing focus. Existing QA controls, warnings, and chart remain functional.
- Normal publication updates preserve attempts/progress, including older active-attempt revisions; explicit failed-state Reset Preview replaces the section with fresh progress. Draft revisions remain excluded.
