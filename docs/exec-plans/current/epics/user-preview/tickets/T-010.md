## Description

Align Preview, Edit, Copy, View Revision, and Edit Title with the bank design and existing design-system components. Keep Preview secondary and preserve all operations and permissions.

## Technical Guidance

`assets/src/apps/bank/EditButton.tsx` renders Edit/Done. `ActivityBank.tsx#onChangeEditing` manages locks and `onDuplicateActivity` uses `createCopy`. `InlineActivityEditor.tsx` supplies copy/history controls and shared `TextEditor` handles titles. Reuse these handlers; scope presentation options to bank usage so other inline editors do not change.

Pass the question title/identity into repeated controls' accessible names, keep visible focus, and hide decorative icons from assistive technology. Use Title Case labels and the [bank-controls design](https://www.figma.com/design/S8qAFhjjlnRyTHCg2Dyb8p/User-Preview-Overhaul?node-id=534-12632).

Existing test references: `test/oli_web/controllers/activity_bank_controller_test.exs`.

## Acceptance criteria

- All five controls match the intended styling and remain keyboard usable with question-specific names. Preview retains MER-6230's isolation and return behavior.
- Edit/Done acquires/releases the existing lock; Copy creates the same banked-question copy; title edits save/cancel; permitted revision history opens its existing route. Preserve Delete.
- Non-admin authors gain no revision-history access, and styling bypasses no locks or validation. Existing controller tests cover history permissions.
- Verify focus through edit/title transitions. Do not redesign bank filters, tags, objectives, editor layout, or non-bank inline editors.
