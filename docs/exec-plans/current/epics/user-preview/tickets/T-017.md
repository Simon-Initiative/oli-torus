## Description

Add Preview Published Course beside the latest publication and provide the Full Course Preview banner and Exit Preview throughout course navigation.

## Technical Guidance

### Size and feasibility

- **Size:** M (3–5 focused engineering days).
- **Single-engineer feasibility:** Good individual assignment after prerequisites. Reuses readiness and identity integration; adds Publish entry, banner, student-only shell, and tab-close exit.
- **Estimate basis:** An engineer familiar with Torus; includes implementation and verification, excludes dependency/review waiting time. This is a planning estimate, not a delivery commitment.

`PublishView` already loads publications/version/diff, and `PublicationDetails` renders the latest-version badge. Add the entry there without redesigning the Publish table. Open MER-6236's shared readiness LiveView in a new tab and announce that behavior. It handles waiting, automatic Learn navigation, failures, and reset; do not build a separate Publish status mechanism.

Adapt `Layouts.template_preview_banner/1` and the delivery layouts for a distinct Full Course Preview context. Keep existing product/template sessions and exit behavior intact. Use MER-6241's preview identity integration and MER-6223's student presentation, including My Notes and learner Class Notes, without an instructor selector. The shared account resolver/reset remains MER-6220's responsibility.

Exit Preview is primary and closes the script-opened tab, assuming success. Do not track an authoring return URL, redirect on close failure, delete preview records, or log out real author/learner accounts.

Existing test references: `test/oli_web/components/delivery/layouts_test.exs`, `test/oli_web/live/publish_live_test.exs`.

## Acceptance criteria

- Published projects expose the entry beside the latest version; unpublished/unauthorized launches are denied. A pending update shows the shared LiveView, then automatically enters Learn in that same tab when ready. The original Publish tab/table remain intact.
- Failed state uses the shared reset explanation/action and exit. Checks never open additional tabs or enqueue update jobs; reconnect/missed notifications retain server-verified behavior.
- Banner/primary exit appear across supported course navigation and remain keyboard usable with visible focus, reflow, and increased zoom. Draft content and instructor controls are absent.
- Normal updates preserve attempts/progress; active graded attempts may retain older content. Failed-state Reset Preview starts a fresh section. Preserve other publication actions, ordinary delivery, author Page Preview, and product/template exits.
- Extend existing publish/controller/layout tests and verify navigation, focus, banner visibility, and tab close in the browser. The parent Story contains the Publish and Learn designs.
