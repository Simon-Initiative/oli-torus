# T-017: Launch Full Course Preview from Publish with a complete preview shell

- **Status:** Created and verified
- **Type:** Sub-task
- **Parent:** [F-007](docs/exec-plans/current/epics/user-preview/tickets/F-007.md)

## Description

## Technical Guidance

### Delivery requirements

Add Preview Published Course beside the latest published version and open Learn in a new tab using the author-linked preview user.

- **Scope:**
  - Confirm the preview section is current before launch. Show updating/failed states, with Reset Preview available after failure.
  - Show a Full Course Preview banner throughout course navigation. The primary Exit Preview action closes the tab, assuming success; the original authoring tab stays open.
  - Use student presentation without an instructor selector.
  - Preserve normal authentication, saved preview progress, the Publish table, and other preview flows.
- **Technical approach:** Extend the existing Publish UI and preview banner/session plumbing, consuming [T-014](docs/exec-plans/current/epics/user-preview/tickets/T-014.md), [T-015](docs/exec-plans/current/epics/user-preview/tickets/T-015.md), [T-016](docs/exec-plans/current/epics/user-preview/tickets/T-016.md)’s readiness/recovery responses, [F-010](docs/exec-plans/current/epics/user-preview/tickets/F-010.md)’s identity handoff, and [T-002](docs/exec-plans/current/epics/user-preview/tickets/T-002.md)’s student presentation. Do not introduce origin-specific return tracking or a close-failure fallback. Proposed implementation details are provisional; required behavior and binding constraints remain mandatory.
- **Acceptance criteria:**
  - **Positive:**
    - **AC1** A published project exposes Preview Published Course beside the latest version. It opens Learn only after [T-014](docs/exec-plans/current/epics/user-preview/tickets/T-014.md), [T-015](docs/exec-plans/current/epics/user-preview/tickets/T-015.md), [T-016](docs/exec-plans/current/epics/user-preview/tickets/T-016.md) confirms the section is current/complete; pending or failed updates show the corresponding response without launch-time refresh. Failed state offers the common Reset Preview action and explains that the shared preview restarts with fresh progress.
    - **AC2** Full Course Preview displays an accessible banner and primary exit throughout supported course navigation; Exit Preview closes the preview tab and leaves the original authoring tab open.
    - **AC3** Keyboard operation, visible focus, narrow screens, and increased zoom work for the launch/banner/exit. Launch opens a new tab and that behavior is announced.
    - **AC4** Project preview launches use the current identity selected by [F-010](docs/exec-plans/current/epics/user-preview/tickets/F-010.md) and preserve normal-use progress plus actual-author authorization, including older revisions retained by existing in-progress graded attempts under during normal use. Explicit failed-state Reset Preview replaces the section and starts with fresh progress.
  - **Negative:**
    - **AC5** Unpublished projects have no working launch action, and unauthorized direct requests are denied by [T-014](docs/exec-plans/current/epics/user-preview/tickets/T-014.md), [T-015](docs/exec-plans/current/epics/user-preview/tickets/T-015.md), [T-016](docs/exec-plans/current/epics/user-preview/tickets/T-016.md).
    - **AC6** Draft content and instructor perspective controls are absent; Full Course Preview does not require [T-003](docs/exec-plans/current/epics/user-preview/tickets/T-003.md).
    - **AC7** Publish table, other publication actions, ordinary student delivery, author Page Preview, and existing product-template exit behavior remain intact.
    - **AC8** Project Full Course Preview has no origin-specific return URL, authoring redirect, or close-failure fallback. Exit Preview closes the tab without deleting preview records or logging out actual author/learner accounts.
- **Size:** M.
- **Feature flags:** None. This Story exposes the first project preview entry together with its completed banner and exit.
