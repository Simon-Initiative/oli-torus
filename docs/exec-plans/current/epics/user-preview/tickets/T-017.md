## Description

## Technical Guidance

### Use the shared readiness LiveView

Preview Published Course opens the shared project launch URL in a new tab and announces that behavior. MER-6236 owns the readiness LiveView: it displays Updating or Failed and automatically redirects to Learn in that tab once the server confirms readiness. Exit Preview remains available while waiting; Failed also offers Reset Preview. There is no Check Again button. The Publish page does not implement a separate readiness interface or monitoring mechanism.

- **Acceptance:** A pending update displays the shared LiveView rather than stale content. Completion automatically redirects to Learn in the same tab without another user action. Checks do not open more tabs or enqueue update jobs. The original Publish tab and its existing functionality remain intact.
- **Acceptance:** Failed state uses the shared reset explanation/action, exit, keyboard/focus behavior, and automatic readiness updates. Refresh/reconnect and missed broadcasts retain the same server-verified readiness behavior. Stale client state cannot bypass the server check.

### Delivery requirements

Add Preview Published Course beside the latest published version and open Learn in a new tab using the author-linked preview user.

- **Scope:**
  - Confirm the preview section is current before launch. Show updating/failed states, with Reset Preview available after failure.
  - Show a Full Course Preview banner throughout course navigation. The primary Exit Preview action closes the tab, assuming success; the original authoring tab stays open.
  - Use student presentation without an instructor selector.
  - Preserve normal authentication, saved preview progress, the Publish table, and other preview flows.
- **Technical approach:** Extend the existing Publish UI and preview banner/session plumbing, consuming [T-014](https://eliterate.atlassian.net/browse/MER-6235), [T-015](https://eliterate.atlassian.net/browse/MER-6236), [T-016](https://eliterate.atlassian.net/browse/MER-6237)’s readiness/recovery responses, [F-010](https://eliterate.atlassian.net/browse/MER-6220)’s identity handoff, and [T-002](https://eliterate.atlassian.net/browse/MER-6223)’s student presentation. Do not introduce origin-specific return tracking or a close-failure fallback. Proposed implementation details are provisional; required behavior and binding constraints remain mandatory.
