# S-016: Reuse author-linked preview users for admin section previews

- **Status:** Approved and pending creation
- **Qualification:** Qualified. Targeted subagent code/test inspection confirms separate shared-admin identity paths in section entry and template preview. S-015’s author-linked resolver can replace those paths; instructor enrollment, owning-admin checks, and legacy fallback exclusion require explicit integration.
- **Lane:** D, third; after S-015 and before S-014 by scheduling preference. S-016 is not a technical prerequisite for project Full Course Preview’s S-014 entry.
- **Ticket:** pending.

## Description

Reuse each admin’s author-linked preview user for section previews instead of the affected per-section shared-admin fallback.

- **Requirements:** [MER-6158](https://eliterate.atlassian.net/browse/MER-6158), R-001, R-010, R-008, R-011. Full requirements are in the epic ticket.
- **Scope:**
  - After actual-admin authorization, ensure the preview user has instructor enrollment in the requested section. Instructor View and Student Preview keep the same identity and enrollment; the URL selects presentation.
  - Integrate controller, LiveView, adaptive, activity, and affected admin template entry paths without a second shared-user substitution.
  - Require the current owning admin and association: generated enrollment alone cannot authorize after logout, role loss, or reset.
  - Exclude current and superseded author-owned preview users from remaining legacy shared fallback queries. Preserve ordinary instructors, normal sessions, and project Full Course Preview’s student-only shell.
- **Technical approach:** Consume S-015’s resolver and durable classification, reuse existing enrollment operations, and wire the selected identity through the existing preview context. Reuse S-002’s route presentation and S-003’s selector. Preserve genuinely required legacy helpers; add no global admin role, migration, or cleanup. Proposed implementation details are provisional; required behavior and binding constraints remain mandatory.
- **Acceptance criteria:**
  - **Positive:**
    - **AC1:** Authorized admins with or without an ordinary learner account enter section Instructor View and Student Preview through the same author-linked preview user from S-015, including adaptive entry.
    - **AC2:** Instructor enrollment is established idempotently in each requested section after actual-admin authorization. Perspective changes preserve the user, enrollment, resource, and original section return destination.
    - **AC3:** Rendering, navigation, activity requests, and affected admin template launch use the intended preview identity without a second shared-fallback substitution.
    - **AC4:** Reset Preview User naturally supplies fresh progress through the new user ID on subsequent project/admin section previews, with instructor enrollment established as needed. Other authors’ preview identities remain unchanged.
    - **AC5:** Actual author authentication, real learner/SSO links and sessions, regular instructors’ real accounts, and non-admin legacy template behavior are preserved.
  - **Negative:**
    - **AC6:** A generated preview-user instructor enrollment alone cannot grant access without its current owning admin author. Logout, loss of admin permission, stale user associations, and forged cross-author/section context cannot bypass authorization.
    - **AC7:** Shared legacy fallback never selects current or superseded author-owned preview users. Unsupported/failed identity provisioning does not silently choose another admin’s user or a shared section user.
    - **AC8:** Regular authors gain no arbitrary real-section access; project Full Course Preview remains student-only without a selector. Author Page Preview/Question Preview retain their existing behavior.
    - **AC9:** No old-user deletion, cleanup, progress migration/clearing, global user-admin role, new admin identity store, or preview-purpose marking of real course/product sections is introduced.
- **Prerequisites:** S-015, S-002, S-003.
- **Size:** L.
- **Sub-tasks (in order; both required for Story acceptance):**
  - **S-016a — Admin preview identity and instructor enrollment.** Adopt the S-015 resolver, ensure section instructor enrollment, enforce owning-admin/current-user authorization, and exclude current/superseded author-owned users from legacy shared fallback. Verify allowed, denied, revoked, concurrent, and reset cases (AC1/2, AC4–7/9).
  - **S-016b — Section and legacy admin preview integration.** Wire section/controller/LiveView/activity/adaptive and affected admin template entries to the identity contract. Verify both perspectives, resource/return preservation, real-session compatibility, reset behavior, and unchanged non-admin/project-preview contexts (AC1–5, AC7–9).
- **Feature flags:** None. This integrates existing section perspectives after the shared identity and selector deliveries are available.

## Local analysis

- **Requirements analysis:**
  - [R-001](docs/exec-plans/current/epics/user-preview/epic.md#r-001-switch-instructor-perspectives-without-losing-context): Admin entry, instructor enrollment in the requested section, both perspectives, same-resource switching, and existing section returns.
  - [R-010](docs/exec-plans/current/epics/user-preview/epic.md#r-010-manage-and-reset-the-author-linked-preview-user): Reuse the same author-linked preview user and Reset Preview User mechanism from S-015. Reset supplies a fresh user ID for subsequent admin section previews as well as project Full Course Preview.
  - [R-008](docs/exec-plans/current/epics/user-preview/epic.md#r-008-keep-preview-controls-accessible-and-authorized) and [R-011](docs/exec-plans/current/epics/user-preview/epic.md#r-011-identify-preview-users-and-sections): Actual-admin authorization, durable generated-user purpose, and preservation of ordinary accounts and sections.
- **Scope analysis:** Integrate S-015’s resolver into admin section-preview and affected admin product/template-preview entry paths. Ensure section-specific instructor enrollment and consistent identity through controller, LiveView, adaptive, and activity requests. Preserve regular instructors’ real identities, non-admin legacy template behavior, project Full Course Preview’s student-only shell, and existing section-return/navigation contracts. Do not create another admin identity store, migrate progress, delete old users, or mark real course/product sections as disposable preview sections.
- **Sources and design:** Operator approval of a unified author-linked preview identity for admins; [Instructor Interface](https://www.figma.com/design/S8qAFhjjlnRyTHCg2Dyb8p/User-Preview-Overhaul?node-id=484-14126) and [Student Preview](https://www.figma.com/design/S8qAFhjjlnRyTHCg2Dyb8p/User-Preview-Overhaul?node-id=484-14996) establish the existing perspectives. S-003 owns the selector UI.
- **Analysis:**
  - **Existing behavior:** `UserAuth.auto_enroll_admin/2` in `lib/oli_web/user_auth.ex` obtains a section-shared hidden instructor when the admin has no current user and writes its token/context. `Sections.ensure_hidden_instructor/1` in `lib/oli/delivery/sections.ex` selects hidden users with instructor enrollment. `AuthorizeSectionPreview.call/2` in `lib/oli_web/plugs/authorize_section_preview.ex` accepts an instructor enrollment or admin author. `PageDeliveryController.page_preview/2` has an unsupported adaptive branch for an admin without a current user.
  - **Template integration:** `TemplatePreview.resolve_launch_identity/2` maps any hidden current user to shared-section fallback. `ProductsController.preview_launch/2` fetches that fallback again. Changing only one resolver would not retain the intended admin identity. Shared-user helpers also have remix, legacy-superactivity, and non-admin callers, so globally deleting them would expand scope.
  - **Remaining gap:** Admin paths do not resolve the per-author preview user or ensure its instructor role. A generated instructor enrollment could grant unintended independent access if normal instructor authorization accepts it without the owning authenticated admin. The shared hidden-user query could also select an author-owned preview user; a current-association-only exclusion fails after that user is superseded by reset.
  - **Verification and uncertainty:** Read-only code and existing-test inspection; no tests or runtime checks run. Development must confirm the complete admin entry inventory, section/context scoping and session preservation, role-revocation behavior at relevant boundaries, and exclusion of current/superseded author-owned users from remaining shared fallback callers.
- **Technical analysis:**
  - **Binding constraints:** Use S-015’s current author-linked preview user for admin preview regardless of whether the admin also has a real learner account. Check actual admin authorization before provisioning or enrollment. Instructor is a section enrollment role, not a global admin grant. Both perspectives keep the same preview user and roles.
  - **Identity and enrollment:** Reuse S-015’s lazy owned-user resolver and existing enrollment operations. Ensure the generated user has the required instructor enrollment in the requested authorized section, without altering the admin’s real learner/instructor accounts. Carry the selected identity through the existing preview context and activity paths while preserving actual-author authentication and normal learner sessions.
  - **Authorization:** Treat generated admin preview users distinctly from ordinary instructors. Require the authenticated owning admin author and current preview-user association at the relevant controller/LiveView/activity boundaries; generated enrollment alone is insufficient after author logout, role loss, or reset. Preserve ordinary instructors’ authorization behavior.
  - **Fallback compatibility:** Replace affected admin auto-enrollment and template-launch shared-fallback selections, including the second fetch in ProductsController. Prevent remaining legacy fallback queries from selecting any author-owned preview user, including superseded rows, using S-015’s durable purpose/ownership information. Keep genuinely required non-admin/legacy helpers and their behavior.
  - **Presentation and reset:** Consume S-002’s route-derived presentation and S-003’s selector. Student Preview uses ordinary URLs; Instructor View uses instructor URLs. Preserve existing section-origin return behavior; the project new-tab policy is separate. After Reset Preview User, subsequent admin entries resolve and enroll the replacement. No attempt/progress clearing, data migration, or cleanup is required.
- **Prerequisite handoffs:** S-015’s author-linked resolver/reset/marker and session foundations; S-002’s route-derived presentation and S-003’s usable selector for end-to-end acceptance. S-001 is transitive.
- **Sizing analysis:** L; reuse the existing resolver, enrollment, presentation, and selector, with coordinated admin entry/API coverage and fallback safety.
