# S-008: Explain unavailable interactions in page preview

- **Status:** Approved and pending creation
- **Qualification:** Qualified. Most unavailable behavior and embedded preview error handling already exist; the gap is accurate, accessible communication in the author-page context.
- **Lane:** B, second by scheduling preference after S-007.
- **Ticket:** pending.

## Description

Explain the five unavailable or conditionally unavailable interaction types in author Page Preview without changing supported interactions.

- **Requirements:** [MER-6158](https://eliterate.atlassian.net/browse/MER-6158), R-006, R-008. Full requirements are in the epic ticket.
- **Scope:**
  - Add accurate information messages for LTI tools, file uploads, directed discussions, configured collaborative spaces, and failed embedded preview-session creation.
  - Keep successful embedded previews working; show the embedded warning only on session failure and the collaboration placeholder only when configured.
  - Use accessible focus/hover information triggers with descriptive names, Escape dismissal, and noninteractive tooltip content. Verify the affected author-preview paths at runtime.
- **Technical approach:** Adapt the existing author-preview branches and previewError handling, and add only the small reusable information presentation needed by these renderers. Verify its initialization in the actual server/React preview contexts; add no new upload, posting, LTI, or collaboration capability. Proposed implementation details are provisional; required behavior and binding constraints remain mandatory.
- **Acceptance criteria:**
  - **Positive:**
    - P1 — Each of the five types shows its exact required message at the affected content or configured placeholder.
    - P2 — Failed embedded session creation shows the unavailable message; a successful session continues to load and interact.
    - P3 — Every information trigger is keyboard reachable and named, references its tooltip, opens on focus/hover, stays visible while focused/hovered unless dismissed, and closes with Escape without moving focus.
    - P4 — Targeted author-page runtime checks cover these five types, their failures, a supported scored activity, and continued review of the remainder of the page.
  - **Negative:**
    - N1 — A successful embedded preview has no unavailable label.
    - N2 — A page without collaboration configuration has no collaboration placeholder.
    - N3 — Tooltips contain no interactive controls; warnings do not disable supported evaluation/hints/reset or claim new upload/posting/LTI capabilities.
    - N4 — Limitation UI does not alter ordinary student delivery or instructor bank-selection preview.
- **Prerequisites:** None.
- **Size:** L.
- **Sub-tasks (in order; both required for Story acceptance):**
  - **S-008a — Accessible limitation presentation and static cases.** Establish the author-page information-trigger behavior; integrate LTI, upload, discussion, and configured collaboration messages. Verify exact copy, modes, keyboard behavior, and supported-page regression.
  - **S-008b — Conditional embedded preview message.** Integrate the same accessible presentation with the existing preview-session failure state; verify success, failed response, and loading behavior without changing the session API.
- **Feature flags:** None.

## Local analysis

- **Requirements analysis:** [R-006](docs/exec-plans/current/epics/user-preview/epic.md#r-006-explain-verified-page-preview-limitations) covers LTI, file upload, directed discussion, conditional OLI embedded-session failure, and page collaborative spaces. Required copy is: LTI — “You cannot interact with this tool in page preview.” File upload — “File uploads are not available in page preview.” Discussion — “Posting to discussions is not available in page preview.” Embedded failure — “Preview is not available for this activity.” Collaborative-space placeholder — “Collaborative spaces are not available in page preview.” [R-008](docs/exec-plans/current/epics/user-preview/epic.md#r-008-keep-preview-controls-accessible-and-authorized) and R-006 require a focusable information button, descriptive name, `aria-describedby`, focus/hover persistence, Escape dismissal without moving focus, noninteractive tooltip content, and placeholders in reading order.
- **Scope analysis:** Add or correct indicators for these five types in author Page Preview and verify their current behavior. Preserve successful embedded sessions and all other supported activity behavior. Do not add upload, posting, LTI interaction, or collaborative-space support. S-009 owns the other four limitation types.
- **Sources and design:** [Design Handoff](https://docs.google.com/document/d/1XrwiN86AETdRxxyoGanQE2pAvl484RHPM6w0prWKk6c/edit); [information tooltip frame](https://www.figma.com/design/S8qAFhjjlnRyTHCg2Dyb8p/User-Preview-Overhaul?node-id=484-13208). Q6 makes runtime verification a delivery acceptance requirement; the unavailable Make prototype adds no scope.
- **Analysis:**
  - **Existing behavior:** `assets/src/components/activities/lti_external_tool/LTIExternalToolDelivery.tsx` already uses a noninteractive `author_preview` branch, with “authoring preview” copy and a hover-only warning. `assets/src/components/activities/oli_embedded/OliEmbeddedDelivery.tsx` already requests `/jcourse/superactivity/preview_context`, handles unsuccessful responses, and renders `previewError` conditionally; successful sessions are supported. These mechanisms should be retained.
  - **Remaining gap:** The LTI warning lacks the required copy and keyboard/Escape tooltip contract. The embedded error uses different copy and an alert rather than the specified information presentation. `assets/src/components/activities/file_upload/FileUploadDelivery.tsx` calls the section/attempt-based upload API without an author-preview branch. `assets/src/components/activities/directed-discussion/DirectedDiscussionDelivery.tsx` passes `writerContext.sectionSlug` to section-backed discussion APIs; it has no page-preview warning branch. `PageEditor.render_page_html/4` supplies project context, and the author-page template has no page collaboration surface or configured placeholder. There is no common author-page indicator satisfying all required semantics.
  - **Verification and uncertainty:** This qualification used code inspection, not executed tests or runtime observation. Upload and discussion failure presentation must be exercised in actual author Page Preview. The existing React `components/common/Tooltip.tsx` wraps a title/Bootstrap tooltip and does not itself express the full contract; `lib/oli_web/components/tooltip.ex` provides the desired semantics through a LiveView hook, whose initialization cannot be assumed in this controller-rendered page. Runtime findings that contradict the approved messages return for a product decision; they do not authorize disabling working interactions.
- **Technical analysis:** Introduce only the small information-trigger presentation needed by these existing renderers. Verify reuse of the existing tooltip behavior in the actual server/React page before choosing its wrapper; do not build a general preview framework. In the LTI author-preview branch, replace the current warning with the required accessible trigger. Add mode-scoped warnings beside file-upload and discussion content without adding their unavailable server operations. Use the existing embedded `previewError` state to show the exact conditional message and preserve successful session rendering/loading. Supply a configured collaboration placeholder from the page's collaboration settings, only when a collaboration space is enabled. Keep indicator semantics reusable by S-009 across server-rendered and React content.
- **Prerequisite handoffs:** No technical dependency on S-007's banner/navigation changes. Reuse the existing author-page entry for implementation and verification. Exit handoff to S-009: an information-trigger integration that works in the actual author-page rendering contexts.
- **Sizing analysis:** L. Five rendering contexts and conditional embedded failure require focused verification, but session creation and LTI suppression already exist.
