## Description

### Keep preview controls accessible and authorized

All changed controls, notes, navigation, and tooltips must support keyboard operation, visible focus, descriptive accessible names, screen-reader state, and reflow at narrow widths and increased zoom. Instructors in the requested section and authors with an admin role may access instructor perspectives; ordinary students and users without those permissions must not receive instructor controls or notes. Keep existing project authorization for author previews and preserve safe return destinations. Each preview-specific requirement above adds its relevant focus, announcement, and failure behavior.

## Shared Requirements

- **Terminology:** Instructor view, Student preview, Page preview, Full course preview.
- **Permissions:** Instructor, Author, Admin
- **Accessibility:** All implementations should clearly label non-text content and be navigable by keyboard and screenreader. Note: we should be switching to “Title case” for buttons because that is how our new design system is intended and it is better for readability.

## Technical Guidance

Apply the shared accessibility and authorization requirements within each affected feature's implementation and acceptance checks. This closed reference creates no separate implementation or verification task. Button labels follow the handoff's Title Case guidance.
