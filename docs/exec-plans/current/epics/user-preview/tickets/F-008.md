**Readiness:** Ready for ticketing

### User Need

As an instructor, I want guidance when I first encounter the preview dropdown so that I can discover it and understand how to switch between instructor view and student preview.

### Acceptance Criteria

**Successful behavior**

- The first time an instructor enters instructor view after this feature is released:
  - Display a dismissible callout anchored to the instructor view dropdown.
  - Highlight the dropdown.
  - Display the message: “Switch between instructor view and student preview.”
- Provide a clearly labeled dismiss control.
- Dismissing the callout removes both the message and the highlight.
- The instructor can use the dropdown while the callout is displayed.
- After dismissal, the callout does not appear again for that instructor across courses, sessions, or devices.

### Accessibility Requirements

- Make the dismiss control keyboard accessible with an accessible name, such as “Dismiss preview guidance.”
- Support Escape to dismiss when focus is within the callout.
- Make the guidance available to screen readers without unexpectedly moving focus.
- Keep keyboard focus visible and unobscured; if dismissal removes the focused control, move focus to the instructor view dropdown.

## Technical Guidance

This section migrates the implementation guidance of `S-006` / `MER-6187`.

### Migrated delivery contract

On first entry to Instructor View, highlight the perspective selector with “Switch between instructor view and student preview.” until explicitly dismissed.

- **Requirements:** [MER-6158](https://eliterate.atlassian.net/browse/MER-6158), R-009, R-008. The feature requirements are in the owning replacement Story; requirement IDs remain reference identifiers in the repository epic.
- **Scope:**
  - Keep the selector usable and provide an accessible dismiss control and Escape behavior within the callout.
  - Store dismissal on the current instructor/user preference record, including the generated admin preview user. Reuse that preference across courses, sessions, and devices for the same user.
  - Preserve visible focus and screen-reader access. Do not store a preference on author accounts or show guidance in selection management and author previews.
- **Technical approach:** Add the dedicated default-false preference to the existing user preference infrastructure and render the callout beside [T-003](docs/exec-plans/current/epics/user-preview/tickets/T-003.md)’s selector. Persist only successful explicit dismissal, handle failed/stale reads, and return focus to the selector when its focused dismiss control is removed. Proposed implementation details are provisional; required behavior and binding constraints remain mandatory.
- **Acceptance criteria:**
  - **Positive:**
    - AC1: First entry to Instructor View shows the exact R-009 message and selector highlight; the selector stays usable.
    - AC2: A keyboard-accessible “Dismiss preview guidance” control or Escape within the callout removes both elements.
    - AC3: Successful dismissal persists on the instructor/user record across courses, sessions and devices where that record is used. Admin previews reuse the same author-linked user across sections; Reset Preview User naturally gives its replacement default preferences.
    - AC4: Screen readers can read the message without automatic focus movement; focus stays visible and falls back to the selector when dismissal removes the focused control.
  - **Negative:**
    - AC5: Display alone does not save dismissal, failed writes are not treated as saved, and stale account reads do not re-show successfully dismissed guidance.
    - AC6: Guidance is absent in bank-selection management and author previews. No author-account preference or separate per-admin dismissal store is added; the generated user naturally owns its own preferences.
- **Size:** M.
- **Feature flags:** None.

- **Scope analysis:** Add a dedicated persisted guidance preference and callout on the [T-003](docs/exec-plans/current/epics/user-preview/tickets/T-003.md) selector surface. Reuse existing user preference infrastructure. Store dismissal on the instructor/current user record, including the dedicated admin preview user when active. Add no preference to author accounts.
- **Sources and design:** [Design Handoff](https://docs.google.com/document/d/1XrwiN86AETdRxxyoGanQE2pAvl484RHPM6w0prWKk6c/edit), Instructor Guidance on Switching Views criteria; [Instructor Interface](https://www.figma.com/design/S8qAFhjjlnRyTHCg2Dyb8p/User-Preview-Overhaul?node-id=484-14126) supplies the selector context. The guidance frame and original embedded mockup are preserved in the handoff requirements above; use them for placement during child UI analysis.
- **Analysis:**
  - **Existing behavior:** `lib/oli/accounts.ex` supplies user preference get/set functions, and `lib/oli/accounts/schemas/user_preferences.ex` defines persisted embedded preference fields. `lib/oli_web/live/sections/assessment_settings/settings_live.ex` demonstrates an existing warning-dismissal pattern. The current preview header is a static label, and the user preference schema has no switcher-guidance dismissal field.
  - **Remaining gap:** The dedicated default-false user preference, callout/highlight, dismiss event, durable write, and focus behavior must be added after the selector exists. Dismissal remains a user preference; different generated user records naturally have different dismissal states.
  - **Verification and uncertainty:** Inspected the user preference schema/accessors and assessment warning behavior; no tests or browser checks run. Fetching a preference by user ID reads the latest record, while passing a previously loaded struct can be stale. Visual placement must be verified against the guidance frame and embedded mockup above. Preference ownership follows the current user supplied by the entry flow, including the admin preview identity supplied by [T-004](docs/exec-plans/current/epics/user-preview/tickets/T-004.md), [T-005](docs/exec-plans/current/epics/user-preview/tickets/T-005.md). Actual-actor authorization remains separate.
- **Technical analysis:** Add the dedicated field only to the user embedded preference changeset, defaulting to false for existing and new users. Use existing user preference get/set functions with the current user ID, including the dedicated admin preview user when active. Add no author preference or separate per-admin dismissal mapping. Render the exact message next to [T-003](docs/exec-plans/current/epics/user-preview/tickets/T-003.md)’s selector without moving focus. A successful explicit dismiss removes the message/highlight and persists the preference; failed writes do not become durable dismissal. Escape only dismisses when focus is within the callout, and removing the focused dismiss control sends focus to the selector. Reuse the existing preference pattern rather than introducing an onboarding table or browser-only store.
- **Prerequisite handoffs:** [T-003](docs/exec-plans/current/epics/user-preview/tickets/T-003.md)’s usable selector and stable focus trigger, with the current instructor user; [T-004](docs/exec-plans/current/epics/user-preview/tickets/T-004.md), [T-005](docs/exec-plans/current/epics/user-preview/tickets/T-005.md) supplies the generated admin identity when used. This does not make [T-004](docs/exec-plans/current/epics/user-preview/tickets/T-004.md), [T-005](docs/exec-plans/current/epics/user-preview/tickets/T-005.md) a prerequisite for the instructor callout work. [F-002](docs/exec-plans/current/epics/user-preview/tickets/F-002.md) is a lane scheduling predecessor, not a technical prerequisite for the preference/callout work.
- **Sizing analysis:** M; existing user preference infrastructure is reusable, while generated-user dismissal, persistence failure and accessible focus need verification.
