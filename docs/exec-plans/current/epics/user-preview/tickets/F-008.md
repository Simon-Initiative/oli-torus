## Description

**Figma frames / prototype:** [Figma](https://www.figma.com/design/S8qAFhjjlnRyTHCg2Dyb8p/User-Preview-Overhaul?node-id=645-12235&t=R18GWzZ0wyxdd55P-1)

### User Need

As an instructor, I want guidance when I first encounter the preview dropdown so that I can discover it and understand how to switch between instructor view and student preview.

### Acceptance Criteria

**Successful behavior**

- The first time an instructor enters instructor view after this feature is released:
  - Display a dismissible callout anchored to the instructor view dropdown.
  - Highlight the dropdown.
  - Display the message: “Switch between instructor view and student preview.”
- Provide a clearly labeled dismiss control.
- Dismissing the callout removes both the message and the highlight.
- The instructor can use the dropdown while the callout is displayed.
- After dismissal, the callout does not appear again for that instructor across courses, sessions, or devices.

### Accessibility Requirements

- Make the dismiss control keyboard accessible with an accessible name, such as “Dismiss preview guidance.”
- Support Escape to dismiss when focus is within the callout.
- Make the guidance available to screen readers without unexpectedly moving focus.
- Keep keyboard focus visible and unobscured; if dismissal removes the focused control, move focus to the instructor view dropdown.

## Technical Guidance

### Size and feasibility

- **Size:** M (3–5 focused engineering days).
- **Single-engineer feasibility:** Good individual assignment. Existing preference patterns support the work; persistent dismissal, failure handling, and accessible focus behavior account for most effort.
- **Estimate basis:** An engineer familiar with Torus; includes implementation and verification, excludes dependency/review waiting time. This is a planning estimate, not a delivery commitment. Story effort includes any sub-tasks; do not add the Story and sub-task estimates together.

### Suggested approach

Add one default-false dismissal preference to `lib/oli/accounts/schemas/user_preferences.ex` and use the existing preference functions in `lib/oli/accounts.ex`. `assessment_settings/settings_live.ex` has an existing warning-dismissal pattern. No new onboarding table or author-account preference is needed.

Store dismissal on the current instructor/user record, including an admin's generated preview user. That makes it consistent across courses, sessions, and devices for that user. Reset Preview User creates a new user with default preferences; it does not preserve the old user's dismissal.

Render the callout beside the selector from [MER-6224](https://eliterate.atlassian.net/browse/MER-6224). Keep the selector usable and exclude bank management and author previews. Follow the exact message, placement, and accessibility requirements above; use the guidance mockup rather than inferring placement from another header design.

### Checks

Persist only an explicit successful dismissal, not display alone. Fetch the preference by user ID when a previously loaded struct could be stale. Failed writes must not be treated as durable dismissal; later reads must not re-show successfully dismissed guidance.

Verify first entry, persisted dismissal across courses/sessions, generated-user reset behavior, write failure, and keyboard/focus behavior. Escape dismisses only while focus is within the callout; removing a focused dismiss control returns focus to the selector. Do not move focus merely to announce the callout. Exact component and field names remain engineering choices.
