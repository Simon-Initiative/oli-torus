# Interactive prototype implementation

Phase 3 scope: [prototype intent](interactives.md#phase-3--connect-build-to-generation-bundling-and-return-to-torus). The sections below record the successive implementation phases and their verification; unrelated working-tree changes remain intact.

## Approach

Use an author-authenticated Build endpoint, a small persisted build record, and short Oban polling jobs. Save only the requested generation inputs through `ActivityEditor.edit/5`, using the page/activity lock already held by the author. Preserve the provider session ID before subsequent work and do not automatically retry an ambiguous session creation. Resume polling after application restarts.

Expose one Agents API function, `finish_interactive`, with no caller-selected destination. The agent creates `/workspace/outputs/interactive.zip`, then calls the function. Torus acknowledges the handoff; after the turn completes it downloads that turn's published artifact. This works for localhost development without exposing an unauthenticated callback or forwarding application/AWS credentials into the sandbox.

The ZIP must contain root `index.html` and `manifest.json`. The manifest contract is `{"version":1,"parts":[{"id":"part_1","objectiveIds":[123]}]}`. Part IDs must be unique and each part must target at least one of the selected skills. This makes the generated-part requirement in the intent concrete; it does not add learner APIs before Phase 5. Reject unsafe ZIP paths and bound archive size/count before extraction into memory. Upload files with MIME types under `interactives/<build UUID>/` in the configured media bucket, then save the bundle reference, generated `authoring.parts`, and revision objective mappings together through the existing activity editing/versioning path. Reject stale inputs or lost edit locks rather than replacing newer author work. Keep an existing successful bundle if a later build fails.

Use Astra (`gpt-6-astra`) and Sol (`gpt-6-sol`) plus a shared supported reasoning-effort dropdown. Pass project-resolved skill IDs/titles and the author's prompt as generation context. Keep secrets server-side, restrict access by project and activity, and expose only safe build status/errors to the author. The frontend uses existing model updates and custom events to apply canonical model/objective results; the server persists completion independently of the browser remaining open.

## Phase 4 — Delivery embedding

Scope: [Phase 4 intent](interactives.md#phase-4--render-the-generated-experience-in-delivery). Use a full-width iframe with a native 576px default height and normal internal scrolling. Show an unavailable state for unbuilt/invalid models. Use iframe sandboxing with scripts enabled. Retain the real origin for cross-origin media so module scripts and same-origin asset fetches work. Reads return JSON values (missing keys return null); writes replace one top-level value. Finalization returns current safe lifecycle/part information. Errors reject with stable codes. No reset operation is exposed.

The iframe SDK uses request/response messages to its parent. Keep the activity active until explicit completion. Require every latest part to be evaluated before calling the existing scoring rollup and page-progress pipeline. Completion is idempotent; evaluated activities reject further mutations. All initial part attempts continue to come from the existing manifest/model lifecycle.

Ship the SDK and its contract into the hosted workspace. ## Delivery sizing and bridge repair

The delivery iframe used a fixed 576px height. It now accepts content-height messages from its own media-origin frame, with SDK observation for content changes, fonts, and viewport-width changes. Document roots use natural height to avoid viewport-minimum feedback loops; generated apps must also avoid viewport-height app wrappers. The delivery API reference records that layout contract.

The bridge listener previously depended on the delivery props object. A same-attempt Torus rerender detached it and discarded an outstanding API response. A regression reproduced that failure before the fix. The listener now remains attached for the lifetime of the bundle/attempt and reads the latest handler through a ref. Layout-effect registration and a retrying read-only context handshake cover startup timing; mutation/finalization calls are never automatically retried.

Existing immutable bundles need the repaired SDK too. A public UUID-only runtime entry publishes content-hashed shared platform assets to the configured media bucket and redirects there. A media-origin bootstrap loads the original HTML, supplies the current SDK before application scripts, and preserves original asset paths. It avoids cross-origin fetch requirements and retains the iframe sandbox/source/origin checks. Original bundle objects and published revisions are unchanged. Publication is cached; failed publication remains retryable.
